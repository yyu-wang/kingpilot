## 1. 任务回顾

### 1.1 目标

把「高风险写操作需要双人复核」从 CLI 的同步输入，升级为**可持久化、可恢复、可审计**的审批单：

- 待审批动作落盘，进程重启不丢
- 双人复核状态机：`pending → approved / rejected / expired`
- 第一确认人与复核人必须是不同用户，且不能是发起人
- 重复审批幂等；拒绝/超时零执行
- 每次状态变化写统一审计流
- 提供列表/详情/通过/拒绝 API

### 1.2 本卡做

| 能力 | 说明 |
|------|------|
| 数据模型 | `PendingAction` / `ApprovalDecision` / 状态枚举 |
| 持久化 | 一个审批单一个 JSON 文件，原子写 + 0600 权限 |
| 状态机 | 双人复核、拒绝、惰性过期、幂等 |
| 服务层 | `ApprovalService`：创建、查询、通过、拒绝 |
| API | 列表 / 详情 / 通过 / 拒绝 |
| 审计 | requested / approved / rejected / expired |
| 测试 | 状态机、持久化恢复、越权、幂等、过期、API 契约 |

### 1.3 本卡明确不做

- **不做审批通过后的执行恢复**：属 M9-T05（本卡只把状态推到 `approved`）
- **不做审批中心 UI**：控制台仍只有对话/会话/Trace；审批 UI 后续再做
- **不做审批人组织架构/汇报线**：T04 用角色白名单，不引入部门树
- **不做多 worker 文件锁**：进程内锁；多实例隔离归 M9-T11
- **不加密落盘**：本地文件 0600；密钥级加密/Vault 归 M9-T10
- **不做通知渠道**：IM/邮件通知后续可接告警通道

### 1.4 验收标准（来自任务卡）

- [ ] 双人复核状态机单测全覆盖
- [ ] 重复审批幂等
- [ ] 拒绝/超时零执行
- [ ] 进程重启后待办可恢复
- [ ] 每次状态变化写审计事件

| 现有能力 | 现状 | T04 如何用 |
|----------|------|------------|
| `HumanInTheLoop` | CLI 同步 `ask()`；`dual_approve` 两次确认 | T05 会把 `dual_approve` 路由到审批单；T04 不修改 HITL |

## 3. 关键设计决策（需审批）

### D1. 审批人准入：`admin` / `manager` 角色白名单

- `APPROVER_ROLES = frozenset({"admin", "manager"})`
- `required_approvers`（来自风险/权限升级）作为展示提示保存
- 实际准入只认 `APPROVER_ROLES`，原因：
  - 现有 `escalate_to` 可能是 `sales_manager` 这类非 `Role` 字面量
  - 直接按字符串匹配会出现「没有任何用户能审批」的死单
- 两条硬规则（任务卡要求）：
  1. 审批人不能是发起人
  2. 两次通过必须是两个不同 `user_id`

### D2. 一个审批单一个 JSON 文件

```
{session_store_dir 同级的 approval_store_dir}/{approval_id}.json
```

- 原子写：`.tmp` → `replace`
- 文件权限 0600，目录 0700
- `approval_id` 白名单校验，拒绝路径穿越
- 读取 fail-closed；列表 fail-soft（坏文件跳过并告警）

Why 不用 SQLite：审批单量小、单条独立、状态机简单；与 Session/Trace/DeadLetter 的本地文件风格一致，不新增 schema 迁移负担。

### D3. 惰性过期，不引入后台定时任务

- 创建时写 `expires_at = now + approval_ttl_seconds`（默认 1800 秒）
- 读取/列表/审批时检查：`pending` 且已过期 → 落盘为 `expired` + 审计
- 没有后台调度器，避免多进程重复过期与额外生命周期
- `status=pending` 的查询不会返回已过期单

### D4. 幂等语义

| 场景 | 结果 |
|------|------|
| 同 `requester + idempotency_key` 重复创建 | 返回原审批单，不新建 |
| 同一审批人重复 `approve` | 200，返回原单，不重复计数 |
| 同一审批人重复 `reject` | 200，返回原单 |
| 已 `approved` 后，未参与审批的人再通过 | 409 `approval_conflict` |
| 已 `rejected` 后再通过 | 409 `approval_conflict` |
| 已 `expired` 后再操作 | 409 `approval_expired` |
| 拒绝优先 | 一个审批人拒绝即 `rejected`，即使已有一票通过 |

### D5. 进程内按审批单加锁

- `ApprovalService` 用 `WeakValueDictionary[str, asyncio.Lock]`
- 单次操作：`load → 校验 → 变更 → save` 全程持锁
- 多 worker 仍有丢失更新风险；本卡部署假设 `workers=1`，与 M9-T01 一致
- 跨进程锁/数据库事务归 M9-T11

### D6. API 只返回审批视图，不返回原始参数

- `PendingAction.arguments` 需要留给 T05 执行，落盘但不通过 API 返回
- API 返回 `summary`（创建时生成，已脱敏）+ 工具名/风险/审批链
- 原因：参数可能含金额、单据号、客户信息；审批人只需要可决策摘要

### D7. 创建入口不在本卡 API

- T04 只有列表/详情/通过/拒绝
- `ApprovalService.create()` 供 M9-T05 的 HITL 网关调用
- 测试可直接调用 service 创建，避免提前造一个「任何人可建审批单」的公开接口

### D8. 审计事件扩展

在 `AuditEventType` 增加：

- `approval.requested`
- `approval.approved`
- `approval.rejected`
- `approval.expired`

审计只记录审批 ID、工具名、风险、审批链与状态，不记录原始参数。

### D9. 评论脱敏与限长

- `comment` 最大 500 字符
- 写入前 `redact_text`，防止审批意见把手机号/证件号带进审计与列表
- 空评论允许

## 4. 数据模型

### 4.1 `models/approval.py`

```python
ApprovalStatus = Literal["pending", "approved", "rejected", "expired"]
ApprovalDecisionType = Literal["approve", "reject"]


class ApprovalDecision(KingPilotBaseModel):
    """一条审批意见（不可变记录）。"""

    approver_id: str = Field(min_length=1, max_length=64)
    decision: ApprovalDecisionType
    comment: str = Field(default="", max_length=500)
    decided_at: datetime


class PendingAction(KingPilotBaseModel):
    """一张待审批动作单。"""

    approval_id: str = Field(default_factory=lambda: uuid4().hex)
    trace_id: str
    session_id: str = ""
    requester_id: str
    requester_role: str
    tool_name: str
    summary: str = ""
    form_id: str = ""
    business_key: str = ""
    risk_score: float = 0.0
    risk_level: str = ""
    required_approvers: list[str] = Field(default_factory=list)
    required_approvals: int = 2
    idempotency_key: str
    status: ApprovalStatus = "pending"
    decisions: list[ApprovalDecision] = Field(default_factory=list)
    created_at: datetime
    updated_at: datetime
    expires_at: datetime
    # 仅供 T05 恢复执行；API 不返回
    arguments: dict[str, Any] = Field(default_factory=dict)
```

约束：

- `required_approvals >= 1`，T04 固定为 2
- `approval_id` 由服务生成，文件名使用该值
- `arguments` 必须 JSON 可序列化（工具参数本身是 JSON）

## 5. 状态机

### 5.1 状态与事件

```
                 approve (1/2)
pending ────────────────────────────────► pending
   │                                          │
   │ reject                                   │ approve (2/2, distinct user)
   ▼                                          ▼
rejected ◄──────────────────────────────  approved
   ▲
   │ now >= expires_at
expired
```

### 5.2 通过

```text
输入：approval_id, approver, comment, now
1. load；不存在 → 404
2. pending 且过期 → 置 expired，审计，返回 409 approval_expired
3. status != pending：
   - 同一审批人已投 approve → 200 幂等返回
   - 其他 → 409 approval_conflict
4. approver == requester → 403 approval_forbidden
5. approver.role not in APPROVER_ROLES → 403 approval_forbidden
6. 该审批人已投 approve → 200 幂等返回
7. 追加 approve 决策
8. approve 决策数 >= required_approvals → status=approved
9. 保存 + 审计
```

### 5.3 拒绝

```text
输入：approval_id, approver, comment, now
1~5 同通过
6. 该审批人已投 reject → 200 幂等返回
7. 追加 reject 决策，status=rejected（拒绝优先）
8. 保存 + 审计
```

### 5.4 过期

- 在 `get/list/approve/reject` 入口统一调用 `_expire_if_needed`
- 仅 `pending` 可过期；`approved/rejected/expired` 不再变化
- 过期落盘失败 → 抛 `ApprovalError`（fail-closed，不返回未持久化状态）

## 7. 服务层

### 7.1 `ApprovalService`

```python
class ApprovalService:
    def __init__(
        self,
        store: FileApprovalStore,
        *,
        audit: AuditLogger | None = None,
        ttl_seconds: int = 1800,
        clock: Callable[[], datetime] | None = None,
    ) -> None: ...

    async def create(
        self,
        *,
        trace_id: str,
        session_id: str,
        requester: UserContext,
        tool_name: str,
        arguments: Mapping[str, Any],
        summary: str,
        form_id: str = "",
        business_key: str = "",
        risk_score: float = 0.0,
        risk_level: str = "",
        required_approvers: Sequence[str] = (),
        idempotency_key: str,
    ) -> PendingAction: ...

    async def get(self, action_id: str, user: UserContext) -> PendingAction: ...
    async def list_for_user(
        self,
        user: UserContext,
        *,
        scope: Literal["inbox", "mine", "all"] = "inbox",
        status: ApprovalStatus | None = None,
        limit: int = 50,
    ) -> list[PendingAction]: ...
    async def approve(
        self, action_id: str, user: UserContext, comment: str = ""
    ) -> PendingAction: ...
    async def reject(
        self, action_id: str, user: UserContext, comment: str = ""
    ) -> PendingAction: ...
```

### 7.2 可见性规则

| scope | 谁可以看 | 内容 |
|-------|----------|------|
| `inbox`（默认） | admin/manager | `pending`、非本人发起、本人未投过票 |
| `mine` | 所有人 | 本人发起的单（全部状态） |
| `all` | 仅 admin | 全部单（可按 status 过滤） |

- 非 admin 请求 `scope=all` → 403 `approval_forbidden`
- `get`：发起人或 admin/manager 可见；其他人 404（不暴露存在性）

### 7.3 `can_decide`

给 API 视图计算：

```python
can_decide = (
    action.status == "pending"
    and user.role in APPROVER_ROLES
    and user.user_id != action.requester_id
    and user.user_id not in {d.approver_id for d in action.decisions}
)
```

### 7.4 审计

```python
AuditEvent(
    event_type="approval.requested",
    action="approval",
    trace_id=action.trace_id,
    user_id=requester.user_id,
    user_role=requester.role,
    tool_name=action.tool_name,
    risk_score=action.risk_score,
    risk_level=action.risk_level,
    approval_chain=[...],
    status="success",
    detail={"approval_id": action.approval_id, "status": action.status},
)
```

- `approved`：每票一条，`approval_chain` 记录当前审批人
- `rejected`：status=`rejected`
- `expired`：status=`blocked`
- 审计写入失败由 `AuditLogger` 降级为 CRITICAL，不阻塞状态机（与 M6 一致）

## 12. 风险与边界

| 风险 | 处理 |
|------|------|
| `required_approvers` 与实际角色不一致 | 准入用 `APPROVER_ROLES`；字段仅展示，避免死单 |
| 审批参数含敏感值 | 落盘 0600；API 只返回脱敏 summary；不写审计 |
| 多 worker 并发丢失更新 | 本卡单 worker；跨进程锁归 M9-T11 |
| 审批单无人处理 | `expires_at` 惰性过期；后续可接提醒 |
| 坏文件导致待办消失 | 列表跳过并告警；`load` fail-closed |
| 审批后无人执行 | T04 明确不执行；T05 负责恢复执行与幂等 |
| 评论注入/超长 | 500 字符上限 + `redact_text` |
| 时间漂移 | 统一 UTC；测试注入 clock |
