## 1. 任务回顾

### 1.1 目标

把散落在 `Settings` 里的密钥读取收敛到一个可替换、可轮换的入口：

- 抽象 `SecretProvider`：按逻辑名取密钥，缺失/不可用 fail-closed
- 三种实现：环境变量（默认，兼容现状）、文件、Vault（HTTP KV v2）
- 轮换：文件/Vault 支持 TTL 自动刷新 + `refresh()` 强制刷新，无需重启
- 零泄漏：日志 / Trace / 异常 / `repr` 不出现明文
- Vault 不可用时默认失败；显式配置后才允许回退到环境变量

### 1.2 本卡做

| 能力 | 说明 |
|------|------|
| `SecretProvider` | `get / get_required / refresh / source` |
| `EnvSecretProvider` | 经 Settings 读取，保持现有 `.env` 用法不变 |
| `FileSecretProvider` | JSON 文件、0600 权限校验、TTL 缓存 |
| `VaultSecretProvider` | Vault KV v2 HTTP、超时、TTL、fail-closed |
| `FallbackSecretProvider` | 主源失败时回退，默认不启用 |
| 工厂 | `build_secret_provider(settings)` 按配置装配 |
| LLM 接入 | 每次请求前取 key，轮换后新请求立即生效 |
| 金蝶接入 | 每次登录前取 app_secret，重登即用新密钥 |
| 测试 | 文件/Vault 契约、轮换、零泄漏、回退策略 |

### 1.3 本卡明确不做

- **不做密钥写入/创建**：Provider 只读；Vault/文件由运维维护
- **不做 HTTP 管理接口**：不暴露 `/secrets` 路由，避免新增攻击面
- **不做 API Key 哈希热轮换**：`api_key_hashes` 是访问控制配置，启动时构建，变更需重启
- **不做 KMS/云厂商 SDK**：只实现 Vault HTTP，避免供应商绑定
- **不做密钥版本历史/回滚 UI**：Vault 自身负责版本
- **不做进程内环境变量热更新**：`env` 模式变更需重启（文件/Vault 才支持热轮换）

### 1.4 验收标准（来自任务卡）

- [ ] Vault 假服务契约测试通过
- [ ] 轮换后新请求使用新密钥且无需重启
- [ ] 日志 / Trace / 异常零明文
- [ ] Vault 不可用时按配置失败或回退（默认失败）

## 3. 关键设计决策（需审批）

### D1. 同步接口 `SecretProvider`，Vault 短超时

```python
class SecretProvider(ABC):
    @property
    @abstractmethod
    def source(self) -> str: ...

    @abstractmethod
    def _load(self, name: SecretName) -> SecretStr: ...

    def get(self, name: SecretName) -> SecretStr:
        return self._load(name)

    def get_required(self, name: SecretName) -> SecretStr:
        value = self.get(name)
        if not value.get_secret_value().strip():
            raise SecretError("密钥未配置", code="secret_missing", secret=name.value)
        return value

    @abstractmethod
    def refresh(self) -> None: ...
```

- 同步原语：`Env`/`File` 天然同步，`Vault` 用 `httpx.Client`（已有依赖）
- Vault 只会在缓存 miss / 登录 / `refresh()` 时访问，默认 TTL 60s、超时 3s；
  单 worker 下可接受，避免把整条调用链改成异步
- 若未来 QPS 上升，可新增 `AsyncSecretProvider` 适配层，不改调用方语义

### D2. 环境变量实现仍经 Settings，不直接读 `os.environ`

```python
class EnvSecretProvider(SecretProvider):
    source = "env"

    def _load(self, name: SecretName) -> SecretStr:
        return self._settings_field(name)
```

- 遵守硬约束：任何模块不得直接读环境变量
- `.env` 兼容：现有 `KINGPILOT_LLM_API_KEY` / `KINGPILOT_KINGDEE_APP_SECRET` 行为不变
- `refresh()` 对 env 是空操作：进程内环境变量不会变，轮换需重启

### D3. 文件实现：JSON + 0600 + TTL

文件格式：

```json
{
  "llm_api_key": "sk-...",
  "kingdee_app_secret": "..."
}
```

- 路径来自 `Settings.secret_file_path`
- **权限 fail-closed**：`mode & 0o077 != 0` → `SecretError(secret_file_permissions)`
- 文件不存在 → `secret_unavailable`；JSON/结构非法 → `secret_invalid`
- 缓存 TTL（默认 60s）；`refresh()` 强制重读
- 原子读取：一次 `read_text`，不边读边解析

### D4. Vault 实现：KV v2 + `X-Vault-Token`

请求：

```text
GET {vault_url}/v1/{mount}/data/{path}
X-Vault-Token: <token>
```

响应：

```json
{"data": {"data": {"llm_api_key": "...", "kingdee_app_secret": "..."}}}
```

- `vault_token` 用 `SecretStr` 承载，**永不出现在 URL/日志/异常**
- 200 但结构不符 → `secret_invalid`
- 403/404 → `secret_unavailable`（不区分是否存在，避免探测）
- 超时/连接失败/5xx → `secret_unavailable`
- 错误消息只含状态码或异常类型，不回显响应体
- TTL 缓存 + `refresh()` 强制刷新

### D5. 回退默认关闭，显式开启才降级

```python
provider = build_secret_provider(settings)
# vault_allow_fallback=False（默认）→ Vault 失败直接抛 SecretError
# vault_allow_fallback=True → FallbackSecretProvider(Vault, Env)
```

- 回退只记 WARNING：`primary=vault code=secret_unavailable fallback=env`
- 不记录任何密钥值
- 默认失败：防止「Vault 配了但实际一直在用环境变量」的静默降级

### D6. LLM 密钥按请求获取

```python
# OpenAICompatibleProvider._chat_once
api_key = self._secrets.get_required(SecretName.LLM_API_KEY).get_secret_value()
resp = await self._http.post(url, headers={"Authorization": f"Bearer {api_key}"})
```

- 构造期仍做一次 `get_required` 校验（fail-fast 保持），但不缓存值
- 轮换后下一次 `plan/reflect/generate` 自动使用新 key
- `RoutingProvider` 与底层 Provider 共享同一个 `SecretProvider`

### D7. 金蝶 app_secret 按登录获取

- `KingdeeAuth._build_sign` 改为从 `SecretProvider` 取 secret
- `_login` 的缺失检查也走 Provider
- 会话有效期内不重登，因此轮换在**下次登录**生效；这是金蝶 Cookie 会话的协议边界

### D8. 零泄漏约束落到可测试点

| 出口 | 约束 |
|------|------|
| 异常 | `SecretError` 消息只含逻辑名/错误码，不含值 |
| 日志 | 只记 `source/name/code`，不记值；Vault token 永不出现 |
| `repr` | Provider 的 `repr` 只显示来源，不显示缓存内容 |
| Trace | 密钥不进入任何模型或工具参数 |
| Settings dump | `SecretStr` 序列化为 `**********` |

### D9. API Key 哈希不纳入热轮换

- `api_key_hashes` 是访问控制配置（存的是哈希），不是运行时下游密钥
- 本卡只把它继续放在 Settings；轮换需重启（后续可并入 T11 租户配置）

### D10. 不新增依赖

- Vault 用现有 `httpx.Client`
- 文件用标准库 `json/pathlib/threading`
- 时间用 `time.monotonic`，测试注入假钟

**实现补充（2026-10-19）**：

- LLM 构造期缺 key 仍抛 `LLMError`（保持既有契约），`SecretError` 作为 `__cause__`
- 回退只在 `secret_unavailable` 时生效；`secret_missing` / `secret_invalid` 直接暴露
- 文件权限过宽使用独立错误码 `secret_file_permissions`，提示 `chmod 600`
- 轮换证据：LLM 两次 `plan` 的 `Authorization` 不同；金蝶两次登录签名不同

```python
class SecretError(KingPilotError):
    """密钥读取异常；code 供调用方分支，消息不含密钥值。"""
    def __init__(self, message: str, *, code: str, secret: str = "") -> None:

        self.secret = secret
```

## 6. 核心实现

### 6.1 `infrastructure/secrets.py`

```python
class FileSecretProvider(SecretProvider):
    source = "file"

    def __init__(self, path: Path, *, ttl_seconds: int, clock: Callable[[], float] = time.monotonic):
        self._path = path
        self._ttl = ttl_seconds
        self._clock = clock
        self._cache: dict[str, SecretStr] | None = None
        self._expires_at = 0.0
        self._lock = threading.Lock()

    def _load(self, name: SecretName) -> SecretStr:
        with self._lock:
            payload = self._payload()
            raw = payload.get(name.value)
            if not isinstance(raw, str) or not raw.strip():
                raise SecretError("密钥未配置", code="secret_missing", secret=name.value)
            return SecretStr(raw)

    def _payload(self) -> dict[str, Any]:
        now = self._clock()
        if self._cache is not None and now < self._expires_at:
            return self._cache
        ...
        self._cache = parsed
        self._expires_at = now + self._ttl
        return parsed

    def refresh(self) -> None:
        with self._lock:
            self._cache = None
            self._expires_at = 0.0
```

Vault 取数：

```python
def _fetch(self) -> dict[str, Any]:
    url = f"{self._base_url}/v1/{self._mount}/data/{quote(self._path, safe='/')}"
    try:
        with httpx.Client(timeout=self._timeout) as client:
            resp = client.get(url, headers={"X-Vault-Token": self._token.get_secret_value()})
    except httpx.HTTPError as exc:
        raise SecretError("Vault 不可用", code="secret_unavailable") from exc
    if resp.status_code in {403, 404}:
        raise SecretError("Vault 密钥不可读", code="secret_unavailable")
    if resp.status_code != 200:
        raise SecretError(f"Vault 返回 HTTP {resp.status_code}", code="secret_unavailable")
    try:
        data = resp.json()["data"]["data"]
    except (ValueError, KeyError, TypeError) as exc:
        raise SecretError("Vault 响应结构不符", code="secret_invalid") from exc
    if not isinstance(data, dict):
        raise SecretError("Vault 响应结构不符", code="secret_invalid")
    return data
```

### 6.2 工厂

```python
def build_secret_provider(settings: Settings) -> SecretProvider:
    mode = settings.secret_provider
    if mode == "env":
        return EnvSecretProvider(settings)
    if mode == "file":
        return FileSecretProvider(settings.secret_file_path, ttl_seconds=settings.secret_cache_ttl_seconds)
    if mode == "vault":
        vault = VaultSecretProvider(...)
        if settings.vault_allow_fallback:
            return FallbackSecretProvider(vault, EnvSecretProvider(settings))
        return vault
    raise SecretError("未知密钥来源", code="secret_config")
```

## 11. 风险与边界

| 风险 | 处理 |
|------|------|
| 同步 Vault 调用阻塞事件循环 | 仅缓存 miss/登录触发，超时 3s；后续可加异步适配 |
| env 模式无法热轮换 | 文档明确；文件/Vault 支持热轮换 |
| Vault KV 版本差异 | 本卡只支持 KV v2，路径固定 `/data/` |
| 文件权限过严导致启动失败 | 错误码明确，提示 `chmod 600` |
| Vault token 泄漏 | SecretStr + 不记日志；错误不回显请求头 |
| 金蝶会话未过期 | 轮换在下次登录生效，符合 Cookie 会话协议 |
| Provider 缓存线程安全 | `threading.Lock` 保护文件/Vault 缓存 |
| API Key 哈希轮换 | 明确不在本卡；变更需重启 |

## 12. 学习指引

1. **为什么要 SecretProvider**：密钥来源会变（env → 文件 → Vault），调用方不应关心来源。
2. **为什么 env 模式仍经 Settings**：统一配置入口是项目红线，避免各模块偷读环境变量。
3. **为什么文件要校验 0600**：同机其他用户可读等于泄漏，权限错误应当场失败。
4. **为什么 Vault 失败默认不回退**：静默回退会让「已经上了 Vault」变成假象。
5. **为什么 LLM key 要按请求取**：Provider 会长期存活，缓存 key 等于轮换失效。
6. **为什么金蝶只在登录取**：Cookie 会话有效期内没有密钥参与，强制重登得不偿失。
7. **为什么错误消息不含响应体**：Vault 响应可能包含敏感字段，异常会被日志与 Trace 采集。
8. **为什么 API Key 哈希不热轮换**：它是访问控制配置而非下游凭证，重启构建更可控。
