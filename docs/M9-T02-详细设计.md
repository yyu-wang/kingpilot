## 1. 任务回顾

### 1.1 目标

在不破坏 DLP、Trace、会话隔离与现有主循环语义的前提下，让客户端在等待最终答复时看到 Agent 的执行阶段：

- `POST /v1/chat/stream` 返回 `text/event-stream`
- 事件覆盖 `plan / guard / execute / reflect / generate`
- 工具事件只暴露名称、状态、耗时，不暴露参数与结果
- 最终答复仍先过 DLP，再作为 `final` 事件发送
- 客户端断连时取消本次运行，不留下半截会话

### 1.2 本卡做

| 能力 | 说明 |
|------|------|
| 事件模型 | `AgentEvent` + `AgentEventSink`，事件 JSON 契约稳定 |
| 主循环埋点 | `AgentCore` 增加可选事件回调；`None` 时行为完全不变 |
| SSE 路由 | `POST /v1/chat/stream`，生产者/消费者队列 + 心跳 |
| 最终答复 | `final` 在「DLP 后 + 会话落盘后」发送 |
| 错误语义 | 流开始前的错误走 JSON；流开始后的错误走 `error` 事件 |
| 断连处理 | 客户端断连 → 取消生产者 → 不保存半截会话 |
| 测试 | 事件顺序、final 与同步接口一致、DLP、错误、心跳 |

### 1.3 本卡明确不做

- **不做逐 token 流式**：DLP 需要完整文本扫描，逐 chunk 扫描存在跨 chunk 绕过风险；保留在 M9 Backlog
- **不做 WebSocket**：单向事件流用 SSE 足够，浏览器原生 `EventSource` 可接
- **不做断线重连/事件回放**：Agent 运行不是幂等查询，重连重跑会重复产生 LLM 成本
- **不做工具结果流式展示**：事件只带元数据，结果统一进最终答复
- **不做控制台 UI**：属 M9-T03

### 1.4 验收标准（来自任务卡）

- [ ] 事件顺序可断言
- [ ] `final` 与同步接口逐字一致
- [ ] DLP 命中时只发安全文案且无原文事件
- [ ] 断连不污染会话
- [ ] 明确不做逐 token 流式

## 2. 现状与约束

| 现有能力 | 对本卡的影响 |
|----------|--------------|
| `AgentCore._run` 按 Phase 0~6 串行执行 | 事件天然有顺序，直接在各 Phase 边界埋点 |
| `AgentCore.run` 在返回前统一过 DLP | `final` 必须取 `run()` 的返回值，不能取 Phase 4 的原始文本 |
| `AgentCore` 每个请求一个实例 | 事件回调可挂在实例上，不存在跨请求串扰 |
| `AppDeps.build_core` 已按请求构造 | 只需增加可选 `event_sink` 参数 |
| `SessionStore` 读-改-写 + 进程内锁 | 流式请求必须整段持锁，避免同会话并发覆盖 |
| `Trace/Audit/DLP` 在 `AgentCore` 内 | SSE 层不重复实现，只消费事件 |
| `api/errors.py` 统一 JSON 错误 | 流开始前复用；流开始后不能再改 HTTP 状态 |

**关键约束**：DLP 优先于流式。任何要发出去的文本必须先完整扫描。

## 3. 关键设计决策（需审批）

### D1. 事件协议：5 类事件 + 稳定 JSON

| event | 触发 | 必带字段 | 禁止字段 |
|-------|------|----------|----------|
| `phase` | 每个阶段开始/结束 | `phase`, `status` | 工具参数、结果 |
| `tool` | 每次工具执行开始/结束 | `tool_name`, `status`（结束带 `latency_ms`） | 参数、结果、错误原文 |
| `final` | 最终答复已过 DLP 且会话已落盘 | `content`, `trace_id`, `session_id` | Trace 全文、工具原始结果 |
| `error` | 流开始后的失败 | `code`, `message` | 异常 context、堆栈、密钥 |
| `done` | 事件流结束（成功或失败都发） | `session_id` | — |

`status` 取值：`start` / `success` / `error`。

### D2. 阶段名称固定为 5 个

任务卡要求的事件阶段：

```
plan → guard → execute → reflect → generate
```

- `reflect` 只在工具执行后需要反思时出现
- 纯聊天（无工具）事件序列：`plan → guard → generate → final → done`
- 护栏拦截：`plan → guard → final → done`（不执行、不反思、不生成）
- LLM 不可用降级：`plan(error) → guard → execute → tool... → final → done`（确定性收尾不走 generate）

### D3. `AgentCore` 只发阶段/工具事件，`final` 由 API 层发

原因：

- `final` 必须在 DLP **之后**、会话保存**之后**发送
- DLP 在 `AgentCore.run` 内完成，但保存由 API 路由负责
- 若 Core 先发 `final`、保存再失败，会出现「已宣布成功又报错」的矛盾顺序

因此：

- Core：`phase` / `tool`
- API 流式路由：`final` / `error` / `done`

### D4. 事件回调是同步、旁路、永不阻塞

```python
AgentEventSink = Callable[[AgentEvent], None]
```

- Core 用 `queue.put_nowait` 作为 sink，不引入 await 点，避免改变主循环时序
- `_emit` 捕获 sink 自身异常：只告警，不中断 Agent
- sink 为 `None` 时零开销、零行为变化

### D5. 生产者/消费者 + 心跳

- 路由返回 `StreamingResponse` 后启动一个 `asyncio.Task` 跑主循环
- 事件写入 `asyncio.Queue`
- 生成器从队列取事件；15 秒无事件发 `: ping\n\n` 注释帧
- 队列无界（单次请求事件量很小），避免反压阻塞主循环

### D6. 断连取消，不写半截会话

- 生成器 `finally` 中取消生产者任务并等待其退出
- 会话保存只在 `core.run` 完整返回后执行；取消不会走到保存
- `SessionStore.save` 本身是原子写（tmp + replace），即使恰好完成也是完整文件
- 断连后 Trace 可能不存在：这是可接受的，因为没有完成的请求

### D7. 流开始前用 JSON 错误，流开始后用 `error` 事件

| 场景 | HTTP | 响应 |
|------|------|------|
| 未认证 / 参数非法 / session_id 非法 | 401 / 422 / 400 | 统一 JSON 错误信封 |
| 流开始后预算耗尽 / 会话读写失败 / 内部异常 | 200 | SSE `error` + `done` |

客户端必须按事件判断业务结果，不能只看 HTTP 200。

### D8. 流式期间整段持有会话锁

- 与同步 `/v1/chat` 一致：`load → run → save` 必须串行
- 第二个同会话请求会在锁上等待，期间仍能收到心跳
- 不同会话互不阻塞

### D9. 不引入新的运行期依赖

SSE 用 Starlette `StreamingResponse` + 标准库 `asyncio/json`，不新增依赖。

## 4. 事件协议细节

### 4.1 JSON 模型

```json
{"event": "phase", "phase": "plan", "status": "start"}
{"event": "phase", "phase": "plan", "status": "success"}
{"event": "tool", "tool_name": "kingdee_query_customer", "status": "start"}
{"event": "tool", "tool_name": "kingdee_query_customer", "status": "success", "latency_ms": 12.3}
{"event": "final", "content": "查询到 1 个客户", "trace_id": "…", "session_id": "…"}
{"event": "error", "code": "budget_exhausted", "message": "服务预算已耗尽，请稍后重试"}
{"event": "done", "session_id": "…"}
```

### 4.2 SSE 帧格式

```
event: phase
data: {"event":"phase","phase":"plan","status":"start"}

```

心跳帧：

```
: ping

```

### 4.3 响应头

| Header | 值 | 原因 |
|--------|----|------|
| `Content-Type` | `text/event-stream; charset=utf-8` | SSE 标准 |
| `Cache-Control` | `no-cache` | 禁止代理缓存 |
| `Connection` | `keep-alive` | 长连接 |
| `X-Accel-Buffering` | `no` | 关闭 Nginx 缓冲，保证逐事件可见 |

### 4.4 错误码（流内）

| code | 触发 |
|------|------|
| `session_invalid` | 会话加载失败/损坏 |
| `session_write_failed` | 会话保存失败 |
| `budget_exhausted` | LLM 预算耗尽 |
| `agent_error` | 其他 `KingPilotError` |
| `internal_error` | 未预期异常 |

## 6. 分步实现

### Step 1：事件模型（`agent/events.py`）

```python
"""Agent 运行事件（M9-T02）：SSE 流式输出的唯一事件契约。"""

from collections.abc import Callable
from typing import Literal

from pydantic import Field

from models.base import KingPilotBaseModel

EventType = Literal["phase", "tool", "final", "error", "done"]
EventStatus = Literal["start", "success", "error"]


class AgentEvent(KingPilotBaseModel):
    """一条可序列化事件。

    Why 单模型而非多个子类：事件量小、字段少；单模型让 SSE 序列化与
    客户端解析只有一条路径，新增字段也不会破坏旧客户端。
    """

    event: EventType = Field(description="事件类型")
    phase: str = Field(default="", description="阶段名（plan/guard/execute/reflect/generate）")
    status: EventStatus | None = Field(default=None, description="开始/成功/失败")
    tool_name: str = Field(default="", description="工具名（仅 tool 事件）")
    latency_ms: float = Field(default=0.0, description="工具耗时（仅 tool 结束事件）")
    content: str = Field(default="", description="最终答复（仅 final 事件）")
    trace_id: str = Field(default="", description="Trace ID（final/done）")
    session_id: str = Field(default="", description="会话 ID（final/done）")
    blocked: bool = Field(default=False, description="是否被 DLP/护栏拦截（final）")
    cancelled: bool = Field(default=False, description="是否被 HITL 取消（final）")
    hallucination_warning: bool = Field(default=False, description="幻觉告警（final）")
    code: str = Field(default="", description="错误码（error）")
    message: str = Field(default="", description="安全错误文案（error）")


AgentEventSink = Callable[[AgentEvent], None]
```

要点：

- 不含 `parameters/result/error` 字段，从模型层杜绝工具数据进事件流
- `exclude_defaults=True` 序列化时自动省略空字段，帧更小

### Step 2：AgentCore 增加事件旁路

`agent/core.py` 构造器末尾增加：

```python
def __init__(
    self,
    ...,
    event_sink: AgentEventSink | None = None,
) -> None:
    ...
    # None = 非流式路径，零行为变化
    self._event_sink = event_sink


def _emit(self, event: AgentEvent) -> None:
    """事件是旁路：sink 自身失败只告警，绝不打断主循环。"""
    if self._event_sink is None:
        return
    try:
        self._event_sink(event)
    except Exception as exc:
        logger.warning("事件推送失败（不影响主循环）: {}", exc)
```

阶段埋点（`_run` 内）：

```python

plan = await self._phase1_plan(...)
self._emit(AgentEvent(event="phase", phase="plan", status="success"))

self._emit(AgentEvent(event="phase", phase="guard", status="start"))
verdict = await self._phase2_guard(...)

self._emit(AgentEvent(event="phase", phase="execute", status="start"))
await self._phase3_execute(...)
self._emit(AgentEvent(event="phase", phase="execute", status="success"))

# 仅当 should_reflect 为真
self._emit(AgentEvent(event="phase", phase="reflect", status="start"))
...
self._emit(AgentEvent(event="phase", phase="reflect", status="success"))

self._emit(AgentEvent(event="phase", phase="generate", status="start"))
await self._phase4_generate(...)
self._emit(AgentEvent(event="phase", phase="generate", status="success"))
```

异常分支：

```python
except LLMUnavailableError:
    self._emit(AgentEvent(event="phase", phase="plan", status="error"))
    ...
```

`reflect` / `generate` 不可用时同理：先发对应阶段的 `status="error"`，再进入确定性降级收尾。

工具埋点（`_phase3_execute`）：

```python
for call in calls:
    self._emit(
        AgentEvent(event="tool", tool_name=call.tool_name, status="start")
    )
    execution = await self._execute_one(call)
    self._emit(
        AgentEvent(
            event="tool",
            tool_name=call.tool_name,
            status="error" if execution.error else "success",
            latency_ms=execution.latency_ms,
        )
    )
    trace.tool_executions.append(execution)
```

降级路径（`_fallback_from_plan`）：

- 已发 `plan(error)`
- `_phase2_guard` / `_phase3_execute` 前后补 `guard` / `execute` 阶段事件
- 确定性收尾不发 `generate`，直接由 API 发 `final`

### Step 4：SSE 路由（`api/streaming.py`）

```python
_HEARTBEAT_SECONDS = 15.0
_SSE_HEADERS = {
    "Cache-Control": "no-cache",
    "Connection": "keep-alive",
    "X-Accel-Buffering": "no",
}

router = APIRouter()


@router.post("/v1/chat/stream")
async def chat_stream(
    payload: ChatRequest,
    request: Request,
    user: Annotated[UserContext, Depends(get_current_user)],
) -> StreamingResponse:
    deps = get_deps(request)
    message = payload.message.strip()
    if not message:
        raise ApiError(422, "empty_message", "消息不能为空")

    session_id = payload.session_id or uuid4().hex[:12]
    store = deps.store_for(user.user_id)
    try:
        store.path_for(session_id)  # 流开始前挡住路径穿越
    except SessionStoreError as exc:
        raise ApiError(400, "session_invalid", "会话 ID 非法") from exc

    return StreamingResponse(
        _stream_chat(deps, user, store, session_id, message),
        media_type="text/event-stream",
        headers=_SSE_HEADERS,
    )
```

生成器与生产者：

```python
async def _stream_chat(
    deps: AppDeps,
    user: UserContext,
    store: SessionStore,
    session_id: str,
    message: str,
) -> AsyncIterator[str]:
    queue: asyncio.Queue[AgentEvent | None] = asyncio.Queue()

    async def produce() -> None:
        try:
            async with deps.locks.get(f"{user.user_id}:{session_id}"):
                try:
                    memory = store.load(session_id)
                except SessionStoreError:
                    queue.put_nowait(
                        AgentEvent(
                            event="error",
                            code="session_invalid",
                            message="会话不存在或已损坏",
                        )
                    )
                    return

                core = deps.build_core(memory, event_sink=queue.put_nowait)
                response = await core.run(message, user_context=user)

                try:
                    store.save(memory)
                except SessionStoreError:
                    queue.put_nowait(
                        AgentEvent(
                            event="error",
                            code="session_write_failed",
                            message="会话保存失败，请重试",
                        )
                    )
                    return

                # final 必须在 DLP 后、落盘后发送
                queue.put_nowait(
                    AgentEvent(
                        event="final",
                        content=response.content,
                        trace_id=str(response.trace_id),
                        session_id=session_id,
                        blocked=response.blocked,
                        cancelled=response.cancelled,
                        hallucination_warning=response.hallucination_warning,
                    )
                )

                if deps.sampler is not None:
                    try:
                        deps.sampler.maybe_sample(response, session_id=session_id)
                    except Exception as exc:
                        logger.warning("在线抽样失败（不影响流式响应）: {}", exc)
        except Exception as exc:
            queue.put_nowait(_error_event(exc))
        finally:
            queue.put_nowait(AgentEvent(event="done", session_id=session_id))
            queue.put_nowait(None)

    task = asyncio.create_task(produce())
    try:
        while True:
            try:
                event = await asyncio.wait_for(queue.get(), timeout=_HEARTBEAT_SECONDS)
            except TimeoutError:
                yield ": ping\n\n"
                continue
            if event is None:
                break
            yield _format_sse(event)
    finally:
        if not task.done():
            task.cancel()
        with suppress(asyncio.CancelledError):
            await task
```

序列化：

```python
def _format_sse(event: AgentEvent) -> str:
    payload = event.model_dump(exclude_defaults=True)
    data = json.dumps(payload, ensure_ascii=False)
    return f"event: {event.event}\ndata: {data}\n\n"
```

错误映射：

```python
def _error_event(exc: Exception) -> AgentEvent:
    if isinstance(exc, ApiError):
        return AgentEvent(event="error", code=exc.code, message=exc.message)
    if isinstance(exc, BudgetExceededError):
        return AgentEvent(
            event="error", code="budget_exhausted", message="服务预算已耗尽，请稍后重试"
        )
    if isinstance(exc, KingPilotError):
        logger.warning("流式请求业务异常: {}", exc)
        return AgentEvent(event="error", code="agent_error", message="Agent 处理失败")
    logger.exception("流式请求未预期异常")
    return AgentEvent(event="error", code="internal_error", message="服务内部错误")
```

| final 一致性 | 同一脚本分别走同步/流式 | 两次 `content` 完全相等 |
| DLP | 答复含手机号 | 流中无手机号，`final.blocked=True` |
| 未认证 | 无 `X-API-Key` | JSON 401 |
| 预算耗尽 | `BudgetExceededError` | 200 + `error.budget_exhausted` + `done` |
| 心跳 | 慢 Provider + 极小心跳 | 出现 `: ping` |
| 断连 | 读首事件后关闭 | 无会话文件、无异常泄漏 |
| sink 异常 | sink 抛 RuntimeError | Agent 正常返回，日志告警 |

## 9. 风险与边界

| 风险 | 处理 |
|------|------|
| 代理缓冲导致事件不实时 | `X-Accel-Buffering: no` + `Cache-Control: no-cache` |
| 客户端只看 HTTP 200 误判成功 | 文档明确：必须解析 `final/error` 事件 |
| 长流占用会话锁 | 同会话请求串行；心跳保持连接；不同会话不阻塞 |
| 断连时 LLM 调用已产生成本 | 取消只能止损后续步骤，已发生的调用无法退款 |
| 流开始前错误与流内错误语义不同 | 设计明确分界；客户端需同时处理 JSON 与 SSE error |
| 事件字段未来扩展 | 单模型 + `exclude_defaults`；新增可选字段不破坏旧客户端 |
| 逐 token 流式的 DLP 绕过 | 本卡不做；Backlog 中要求先解决跨 chunk 扫描 |

## 10. 学习指引

1. **SSE vs WebSocket**：为什么单向事件流不需要 WebSocket？
2. **生产者/消费者**：为什么主循环写入队列、路由从队列读，而不是在 Phase 里直接 `yield`？
3. **DLP 与流式冲突**：为什么不能边生成边发送 token？
4. **同步 sink**：为什么事件回调不加 `await`？加了会怎样改变主循环时序？
5. **断连语义**：`StreamingResponse` 生成器被关闭时，如何保证后台任务被取消？
6. **HTTP 状态与事件状态**：为什么流开始后只能用 `error` 事件表达失败？
7. **心跳**：没有心跳时，代理/浏览器可能怎样处理长连接？
8. **事件脱敏**：为什么工具事件连 `parameters` 都不能带？
