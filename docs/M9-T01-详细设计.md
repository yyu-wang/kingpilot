## 1. 任务回顾

### 1.1 目标

把已验证的 Agent 内核接到 HTTP 上，形成可被前端/外部系统调用的服务基座：

- API Key 认证 → `UserContext`（角色 + 数据域）
- 按用户隔离会话，杜绝跨用户读取
- 统一错误契约，响应不泄漏密钥、堆栈、敏感上下文
- API 路径复用同一套 `AgentCore` / 安全 / DLP / Trace / Audit

### 1.2 本卡做

| 能力 | 说明 |
|------|------|
| 服务基座 | `api/` 包 + FastAPI app factory + lifespan |
| 认证 | `X-API-Key` → SHA-256 哈希配置 → `UserContext` |
| 对话接口 | `POST /v1/chat`，多轮、会话落盘、返回 trace_id |
| 会话接口 | `GET /v1/sessions`、`GET /v1/sessions/{id}`（仅本人） |
| 健康检查 | `GET /v1/health`（无认证、无敏感信息） |
| 错误契约 | 统一 `{"error": {"code", "message"}}`，不泄漏内部细节 |
| 并发保护 | 同一用户同一会话串行处理（进程内锁） |
| 可观测 | Trace/Audit/DLP/在线抽样在 API 路径同样生效 |

### 1.3 本卡明确不做

- **不做写操作开放**：API 模式所有 `confirm` / `dual_approve` 一律拒绝，写操作等 M9-T04/T05 审批中心
- **不做流式**：SSE 属 M9-T02
- **不做 Web 控制台**：属 M9-T03
- **不做多租户**：按用户隔离在本卡完成，租户级隔离属 M9-T11
- **不做密钥轮换/Vault**：属 M9-T10
- **不做限流/TLS**：部署在可信内网或网关之后，由网关承担限流与 TLS 终止

### 1.4 验收标准（来自任务卡）

- [ ] TestClient 完成多轮对话
- [ ] 两个用户互相看不到对方会话（404/403）
- [ ] API 路径同样产生 Trace/Audit 并过 DLP
- [ ] CLI 行为零变化
- [ ] 密钥/堆栈不出现在错误响应

## 2. 现状与可复用资产

| 现有模块 | 本卡如何复用 | 禁止事项 |
|----------|--------------|----------|
| `agent/core.py::AgentCore` | 每个请求构造一个实例，注入当次 `MemoryStore` | 不在 API 层复制规划/执行逻辑 |
| `agent/session_store.py::SessionStore` | 每个用户一个实例，根目录按用户命名空间 | 不直接用全局根目录 |
| `agent/memory.py::MemoryStore` | 通过 `SessionStore.load()` 恢复，`save()` 落盘 | 不绕过 store 直接读写 JSON |
| `safety/engine.py::SafetyLayer` | 进程级共享，HITL 注入 `DenyConfirmationIO` | 不在 API 层跳过安全审查 |
| `observability/tracing.py::TraceStore` | 进程级共享，Trace 内含 `user_id/session_id` | 不默认把完整 trace 返回给客户端 |
| `observability/audit.py::AuditLogger` | 进程级共享，DLP/Guard/预算事件继续入流 | 不新建第二套审计出口 |
| `agent/providers.py::get_provider` | 进程级共享一个 Provider | 不在每次请求重建 Provider（预算会重置） |
| `kingdee/client.py::KingdeeClient` | 进程级共享，lifespan 管理连接 | 不在路由内临时建客户端 |
| `governance/prompt_registry.py` | 启动期加载，API 先固定稳定版 | 见 D3 的边界说明 |
| `governance/online_sampler.py` | 进程级共享，对话后旁路抽样 | 抽样失败不影响主响应 |

**核心原则**：`api/` 只做协议适配与依赖装配，业务能力全部回到现有模块。

## 3. 关键设计决策（需审批）

### D1. API Key 只存 SHA-256 哈希，不存明文

- 配置项：`KINGPILOT_API_KEY_HASHES`，JSON 对象：`{"<64位小写hash>": {"user_id": "...", "role": "...", "data_scope": {...}}}`
- 请求头：`X-API-Key: <明文 key>`
- 服务端：`sha256(presented)` 后与配置逐项 `hmac.compare_digest`，命中即身份
- 空配置 = 所有请求 401（安全默认）
- 配置格式非法 / `user_id` 非法 / `role` 非法 → **启动失败**（fail-closed）

理由：仓库、日志、进程环境里都不出现明文 key；哈希不可逆，泄露后无法直接冒用。

### D2. 会话按用户命名空间隔离

```
原来（CLI）：{session_store_dir}/{session_id}.json
API：       {session_store_dir}/users/{user_id}/{session_id}.json
```

- `SessionStore` 本身不改，API 层为每个用户构造 `SessionStore(root / "users" / user_id)`
- 用户 B 即使猜到用户 A 的 `session_id`，也只会在自己的目录查不到 → 404
- `user_id` 必须匹配 `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`，防止路径穿越

### D3. 进程级共享一个 Provider（已知边界）

- 预算/成本是进程级语义，Provider 必须共享，否则每个请求重建会把预算重置
- API 启动时 `rollout_key=""`，Prompt 固定走 `active` 稳定版
- **边界**：M8-T04 的「按会话 Prompt 灰度」在 API 路径暂不生效；CLI 不受影响
- 后续在 M9-T02 事件流稳定后，再评估按会话灰度（需要 Provider 支持每请求 rollout_key 且不破坏共享预算）

### D4. API 模式写操作默认拒绝

- `SafetyLayer` 的 `ConfirmationIO` 注入 `DenyConfirmationIO`：`ask()` 永远返回 `False`
- `confirm` / `dual_approve` → 取消，不执行任何写操作
- 这是本卡的安全边界：审批中心（M9-T04/T05）落地前，API 只读

### D5. 同用户同会话串行（进程内锁）

- `SessionStore.load → AgentCore.run → save` 是读-改-写，必须串行
- `SessionLocks` 用 `WeakValueDictionary[str, asyncio.Lock]` 按 `user_id:session_id` 加锁
- **边界**：只保证单进程；多 worker 部署需要文件锁/SQLite，归 M9-T11 或后续任务。本卡部署参数固定 `workers=1`

### D6. 统一错误信封，不回传内部细节

```json
{"error": {"code": "unauthorized", "message": "无效或缺失的 API Key"}}
```

- 不回传 `str(exc)`、`context`、堆栈、上游响应体、API Key/哈希
- 参数校验错误由自定义处理器接管，避免 FastAPI 默认把请求原值回显

### D7. FastAPI/uvicorn 提升为运行期依赖

- 当前只在 `dev` 可选依赖里（给 sandbox 用）
- API 是产品能力，必须进入 `[project].dependencies`
- 同时把 `api` 加入 hatch wheel packages、coverage source、isort first-party

### D8. 本卡不做流式

- 同步 JSON 响应先跑通认证、隔离、错误契约、可观测
- SSE 在 T02 单独做，避免把 DLP 与流式语义混在一张卡里

## 4. API 契约

### 4.1 端点总览

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| GET | `/v1/health` | 否 | 健康检查，仅返回 `{"status":"ok"}` |
| POST | `/v1/chat` | 是 | 单轮/多轮对话 |
| GET | `/v1/sessions` | 是 | 当前用户会话列表 |
| GET | `/v1/sessions/{session_id}` | 是 | 当前用户单个会话元信息 |

### 4.2 `POST /v1/chat`

请求：

```json
{
  "message": "查询客户 CUS001 的销售订单",
  "session_id": "可选；不传则服务端生成"
}
```

响应 200：

```json
{
  "session_id": "a1b2c3d4e5f6",
  "trace_id": "6f1c2d9e-...",
  "content": "助手答复",
  "blocked": false,
  "cancelled": false,
  "hallucination_warning": false
}
```

说明：

- `message` 去空白后为空 → 422 `empty_message`
- `session_id` 不存在 → 按新会话处理（与 CLI 一致）
- `session_id` 非法（路径穿越等）→ 400 `session_invalid`
- 会话保存失败 → 500 `session_write_failed`（不返回未持久化的答复）

### 4.3 `GET /v1/sessions`

```json
{
  "sessions": [
    {"session_id": "a1b2c3d4e5f6", "rounds": 3, "updated_at": "2026-10-19T10:00:00Z"}
  ]
}
```

只列当前用户目录下的会话。

### 4.4 错误码

| HTTP | code | 触发场景 |
|------|------|----------|
| 401 | `unauthorized` | 缺失/错误 API Key |
| 422 | `invalid_request` | 请求体不符合 schema |
| 422 | `empty_message` | 消息为空 |
| 400 | `session_invalid` | session_id 非法或会话文件损坏 |
| 404 | `session_not_found` | 会话不存在或不属于当前用户 |
| 500 | `session_write_failed` | 会话落盘失败 |
| 503 | `budget_exhausted` | LLM 预算耗尽 |
| 502 | `agent_error` | 其他 Agent 业务异常（不含内部细节） |
| 500 | `internal_error` | 未预期异常 |
| 503 | `not_ready` | lifespan 尚未完成 |

### Step 3：API Key 目录与认证依赖

`api/auth.py` 关键代码（`get_current_user` 实际放在 `api/deps.py`，避免 `auth ↔ deps` 循环导入）：

```python
_HASH_RE = re.compile(r"^[0-9a-f]{64}$")
_USER_ID_RE = re.compile(r"^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$")


class ApiKeyIdentity(KingPilotBaseModel):
    user_id: str = Field(min_length=1, max_length=64, pattern=_USER_ID_RE.pattern)
    role: Role
    data_scope: dict[str, Any] = Field(default_factory=dict)


@dataclass(frozen=True)
class ApiKeyDirectory:
    """哈希 → 身份目录；只读，启动期构建一次。"""

    _records: Mapping[str, ApiKeyIdentity]

    @classmethod
    def from_settings(cls, settings: Settings) -> "ApiKeyDirectory":
        raw = settings.api_key_hashes.get_secret_value().strip()
        if not raw:
            return cls({})
        try:
            payload = json.loads(raw)
        except ValueError as exc:
            raise ApiKeyConfigError("API Key 配置不是合法 JSON") from exc
        if not isinstance(payload, dict):
            raise ApiKeyConfigError("API Key 配置必须是 JSON 对象")
        records: dict[str, ApiKeyIdentity] = {}
        for index, (key_hash, value) in enumerate(payload.items()):
            if not isinstance(key_hash, str) or not _HASH_RE.fullmatch(key_hash):
                raise ApiKeyConfigError(f"第 {index} 条 API Key 哈希格式非法")
            try:
                records[key_hash] = ApiKeyIdentity.model_validate(value)
            except ValidationError as exc:
                raise ApiKeyConfigError(f"第 {index} 条 API Key 身份配置非法") from exc
        return cls(records)

    def authenticate(self, presented: str) -> ApiKeyIdentity | None:
        """常量时间比较；遍历全部条目，避免按位置提前返回。"""
        digest = hashlib.sha256(presented.encode("utf-8")).hexdigest()
        matched: ApiKeyIdentity | None = None
        for key_hash, identity in self._records.items():
            if hmac.compare_digest(digest, key_hash):
                matched = identity
        return matched


async def get_current_user(
    request: Request,
    x_api_key: Annotated[str | None, Header(alias="X-API-Key")] = None,
) -> UserContext:
    if not x_api_key:
        raise ApiError(401, "unauthorized", "无效或缺失的 API Key")
    identity = get_deps(request).api_keys.authenticate(x_api_key)
    if identity is None:
        raise ApiError(401, "unauthorized", "无效或缺失的 API Key")
    return UserContext(
        user_id=identity.user_id,
        role=identity.role,
        data_scope=identity.data_scope,
        ip_address=request.client.host if request.client else "",
    )
```

要点：

- 哈希比较用 `hmac.compare_digest`，不泄露匹配位置
- 401 统一文案，不区分「key 不存在」和「key 错误」
- `user_id` 正则从配置入口就挡住路径穿越

### Step 4：会话锁与依赖容器

`api/deps.py`：

```python
class DenyConfirmationIO:
    """API 模式确认通道：一律拒绝，写操作等 M9-T04/T05 审批中心。"""

    async def ask(self, prompt: str) -> bool:
        return False


class SessionLocks:
    """进程内按会话串行；WeakValueDictionary 避免锁无限堆积。"""

    def __init__(self) -> None:
        self._locks: WeakValueDictionary[str, asyncio.Lock] = WeakValueDictionary()

    def get(self, key: str) -> asyncio.Lock:
        lock = self._locks.get(key)
        if lock is None:
            lock = asyncio.Lock()
            self._locks[key] = lock
        return lock


@dataclass
class AppDeps:
    settings: Settings
    provider: LLMProvider
    client: KingdeeClient
    registry: ToolRegistry
    safety: SafetyLayer
    trace_store: TraceStore
    audit: AuditLogger
    sampler: OnlineSampler | None
    api_keys: ApiKeyDirectory
    session_root: Path
    locks: SessionLocks = field(default_factory=SessionLocks)

    def store_for(self, user_id: str) -> SessionStore:
        return SessionStore(self.session_root / "users" / user_id)

    def build_core(self, memory: MemoryStore) -> AgentCore:
        return AgentCore(
            self.provider,
            self.registry,
            self.client,
            self.settings,
            memory=memory,
            safety=self.safety,
            trace_store=self.trace_store,
            audit=self.audit,
        )


def get_deps(request: Request) -> AppDeps:
    deps = getattr(request.app.state, "deps", None)
    if deps is None:
        raise ApiError(503, "not_ready", "服务尚未就绪")
    return cast(AppDeps, deps)
```

### Step 5：app factory 与 lifespan

`api/app.py` 关键代码：

```python
@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    settings: Settings = app.state.settings
    setup_logging()
    audit = AuditLogger(JsonlAuditSink(settings.audit_log_path))
    audit.subscribe(AlertEngine().observe)

    async with AsyncExitStack() as stack:
        # Provider/Client 由本进程创建时，退出时一并关闭；测试注入时不动外部资源
        provider = app.state.provider_override
        if provider is None:
            prompts = PromptRegistry(settings.prompts_dir)
            provider = get_provider(settings, audit=audit, prompts=prompts, rollout_key="")
            stack.push_async_callback(provider.aclose)

        client = app.state.client_override
        if client is None:
            client = await stack.enter_async_context(KingdeeClient(settings))

        registry = build_default_registry()
        safety = SafetyLayer(registry, client, DenyConfirmationIO(), audit=audit)
        sampler = (
            OnlineSampler(
                settings.online_sample_dir,
                sample_rate=settings.online_sample_rate,
                max_per_day=settings.online_sample_max_per_day,
            )
            if settings.online_sample_rate > 0
            else None
        )
        app.state.deps = AppDeps(
            settings=settings,
            provider=provider,
            client=client,
            registry=registry,
            safety=safety,
            trace_store=TraceStore(settings.trace_store_dir),
            audit=audit,
            sampler=sampler,
            api_keys=ApiKeyDirectory.from_settings(settings),
            session_root=settings.session_store_dir,
        )
        yield


def create_app(
    settings: Settings | None = None,
    *,
    provider: LLMProvider | None = None,
    client: KingdeeClient | None = None,
) -> FastAPI:
    resolved = settings or get_settings()
    app = FastAPI(title="KingPilot API", version="0.1.0", lifespan=lifespan)
    app.state.settings = resolved
    app.state.provider_override = provider
    app.state.client_override = client
    install_error_handlers(app)
    app.include_router(router)
    return app
```

要点：

- `AsyncExitStack` 统一管理「谁创建、谁关闭」，测试注入时不误关
- 依赖在 lifespan 内构建，路由拿到的都是已就绪对象
- `provider` 共享，预算/成本进程级一致

### Step 6：路由

`api/routes.py` 的 chat 核心：

```python
@router.post("/v1/chat", response_model=ChatResponse)
async def chat(
    payload: ChatRequest,
    request: Request,
    user: Annotated[UserContext, Depends(get_current_user)],
) -> ChatResponse:
    deps = get_deps(request)
    message = payload.message.strip()
    if not message:
        raise ApiError(422, "empty_message", "消息不能为空")

    session_id = payload.session_id or uuid4().hex[:12]
    store = deps.store_for(user.user_id)

    # 读-改-写整体加锁：避免同会话两个请求互相覆盖
    async with deps.locks.get(f"{user.user_id}:{session_id}"):
        try:
            memory = store.load(session_id)
        except SessionStoreError as exc:
            raise ApiError(400, "session_invalid", "会话不存在或已损坏") from exc

        response = await deps.build_core(memory).run(message, user_context=user)

        try:
            store.save(memory)
        except SessionStoreError as exc:
            raise ApiError(500, "session_write_failed", "会话保存失败，请重试") from exc

        if deps.sampler is not None:
            try:
                deps.sampler.maybe_sample(response, session_id=session_id)
            except Exception as exc:
                logger.warning("在线抽样失败（不影响响应）: {}", exc)

    return ChatResponse(
        session_id=session_id,
        trace_id=str(response.trace_id),
        content=response.content,
        blocked=response.blocked,
        cancelled=response.cancelled,
        hallucination_warning=response.hallucination_warning,
    )
```

@router.get("/v1/sessions/{session_id}", response_model=SessionSummary)
async def get_session(
    session_id: str,
    request: Request,
    user: Annotated[UserContext, Depends(get_current_user)],
) -> SessionSummary:
    store = get_deps(request).store_for(user.user_id)
    try:
        store.path_for(session_id)  # 先做 ID 白名单校验（防路径穿越）

            return SessionSummary(
                session_id=info.session_id,
                rounds=info.rounds,
                updated_at=info.updated_at,
            )
    raise ApiError(404, "session_not_found", "会话不存在")

### Step 7：统一错误处理

`api/errors.py`：

```python
class ApiError(Exception):
    def __init__(self, status_code: int, code: str, message: str) -> None:
        super().__init__(message)
        self.status_code = status_code
        self.code = code
        self.message = message


def install_error_handlers(app: FastAPI) -> None:
    @app.exception_handler(ApiError)
    async def _api_error(request: Request, exc: ApiError) -> JSONResponse:
        return _envelope(exc.status_code, exc.code, exc.message)

    @app.exception_handler(RequestValidationError)
    async def _invalid_request(request: Request, exc: RequestValidationError) -> JSONResponse:
        return _envelope(422, "invalid_request", "请求参数不合法")

    @app.exception_handler(BudgetExceededError)
    async def _budget(request: Request, exc: BudgetExceededError) -> JSONResponse:
        return _envelope(503, "budget_exhausted", "服务预算已耗尽，请稍后重试")

    @app.exception_handler(KingPilotError)
    async def _agent_error(request: Request, exc: KingPilotError) -> JSONResponse:
        logger.warning("API 业务异常: {}", exc)
        return _envelope(502, "agent_error", "Agent 处理失败")

    @app.exception_handler(Exception)
    async def _internal(request: Request, exc: Exception) -> JSONResponse:
        logger.exception("API 未预期异常")
        return _envelope(500, "internal_error", "服务内部错误")
```

`_envelope` 只序列化 `code/message`，绝不带 `context` 或堆栈。

## 8. 风险与边界

| 风险 | 处理 |
|------|------|
| 多 worker 下进程内锁失效 | 本卡部署固定 `workers=1`；多实例方案归 M9-T11 |
| API 路径 Prompt 灰度不生效 | 已知边界（D3）；T02 后评估按会话灰度 |
| 写操作被一律拒绝 | 设计如此（D4）；审批中心 T04/T05 开放 |
| 无 TLS/限流 | 部署在网关之后，由网关终止 TLS 与限流 |
| API Key 轮换 | 本卡需重启加载哈希配置；Vault/轮换归 T10 |
| 会话/审计文件跨用户读取 | API 只暴露本人目录；Trace/Audit 不通过 API 返回 |
| 共享 Provider 预算为进程级 | 与现有 Settings 语义一致；租户级预算归 T11 |

## 9. 学习指引（实现前建议理解）

1. **ASGI 与 lifespan**：为什么连接池要在 lifespan 里创建/关闭，而不是模块导入时创建？

5. **目录命名空间**：为什么按用户分子目录比「在文件名里拼 user_id」更安全？

8. **零业务逻辑路由**：如果 API 层复制一份 AgentCore，后续 M9-T02/T04 会付出什么代价？
