## 0. 使用说明

### 0.1 测试身份

| 身份 | 角色 | API Key | 用途 |
|------|------|---------|------|
| alice | admin | 登录框已预填 | 查询、销售订单/采购订单发起 |
| bob | manager | `bob-manager-key-2026` | 单票/双票审批 |
| carol | manager | `carol-manager-key-2026` | 双票审批第二人 |
| wanda | warehouse | `wanda-warehouse-key-2026` | 采购入库发起 |

> 发起人不能审批自己的单：alice 发起 → bob/carol 审批；wanda 发起 → bob/carol 审批。
> 管理后台：`http://127.0.0.1:8080/admin/`，仅 alice（admin）可登录。

### 0.2 启动与复位

```bash
make sandbox          # 终端 1：仿真沙箱 127.0.0.1:8000
make serve            # 终端 2：Web/API 127.0.0.1:8080
```

**复位测试数据**：停止并重启沙箱即可恢复 40 条采购订单 / 130 条销售订单 / 14 条入库单；新建单号重新从 `SO900001`、`PO900001`、`CGRK900001` 开始。
建议每轮完整测试前重启一次沙箱，避免上一轮写操作改变单据状态。

## 12. 通过标准

- 第 1~11 节除「已知问题」外全部通过（`[x]`）。
- 写流程必须满足：
  - 创建/提交 = 1 票，审核/反审核/删除 = 2 票；
  - 发起人不能审批自己的单；
  - 审批通过后恰好执行一次；
  - 执行失败时数据不变，错误信息可读。
