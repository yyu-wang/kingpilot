## 一、方法与口径

- 对话类用例通过 `POST /v1/chat` 驱动，再用 `GET /v1/traces/{trace_id}` 校验工具调用、Guard、最终答复。
- 写流程通过 `/v1/approvals` 接口完成「通过」动作（与 UI 点「通过」等价），审批人固定为 bob / carol。
- 数据校验走 `GET /v1/admin/datasets/{kind}`（销售订单 / 采购订单 / 采购入库单）。
- UI 类用例在真实浏览器中逐项点击、输入、读取 DOM 与 computed style。
- 为避免环境干扰，每轮完整测试前重启一次仿真沙箱，写流程只操作自建单号，不改动种子数据。
- 判定口径：`PASS` 为满足预期；`FAIL` 为与预期不符；断言只做关键词/状态校验，个别语义正确的回答已人工复核并注明。

## 三、失败项详情

### P1：采购订单「审核」被规划成查询，写流程中断（3 个直接失败 + 2 个连锁失败）

| 用例 | 现象 | 证据 |
|---|---|---|
| PO-W04 审核采购订单 PO900001 | 返回「已查询到订单…如需推进请自行在 ERP 操作」，未进入审批 | Trace planning 只调用了 `erp_query_purchase_order`，未调用 `erp_audit_purchase_order` |
| PO-W11 审核采购订单 PO000004 | 同上（且出现一次 HTTP 200 + 空回复） | 规划工具同为查询 |
| IN-W12-AUD 审核采购订单 PO900002 | 同上 | 规划工具同为查询 |
| PO-W05 / PO-W06 | 因 W04 未完成审核，订单停在 B，反审核/删除被执行期拒绝 | `当前状态 B 不允许反审核/删除: PO900001` |

影响：采购订单创建、提交均正常，但「审核」及之后的链路无法通过自然语言完成；销售订单同名指令可正常触发审核，说明不是通用权限问题，而是采购审核工具的选择/描述问题。

相关实现：[pur_order_write.py](file:///Users/wangyu/Desktop/个人/demo/KingPilot/kingdee/endpoints/pur_order_write.py)

### P1：登录失败提示不可见（UI-03）

- 现象：输入错误 Key 后停留登录页，但「API Key 无效或已过期」仅存在约 1 毫秒即被清空，用户看不到失败原因。
- 原因：`handleLogin` 并发请求 `/v1/sessions` 与 `/v1/me`，两个 401 各自触发 `logout()`，后一次 `logout()` 覆盖了 catch 写入的错误文案。
- 位置：[app.js](file:///Users/wangyu/Desktop/个人/demo/KingPilot/api/static/app.js#L189-L207)、[logout()](file:///Users/wangyu/Desktop/个人/demo/KingPilot/api/static/app.js#L163-L187)

### P2：写操作前置校验不足，业务错误依赖执行期兜底

| 用例 | 现象 | 说明 |
|---|---|---|
| IN-W08 供应商与源单不一致 | 发起时返回 202 进入审批，执行期才报「供应商与源采购订单不一致: 4002 != SUP001」 | 数据未落库（新增单据=False），但用户先看到审批单、后看到失败 |
| IN-W12 新采购订单作为源单 | 源采购订单仍为 B（未审核），仍允许发起入库并返回 202 | 违反「源采购订单必须已审核」预期；执行期会失败，但前置未拦截 |

相关校验现位于仿真沙箱执行层：[inbound_store.py](file:///Users/wangyu/Desktop/个人/demo/KingPilot/sandbox/kingdee_stub/inbound_store.py#L82-L94)

### P2：网络回复为空（2 例）

- PO-W11、IN-W10 在完整跑批中各出现一次 `HTTP 200` + `content=""`（前期手工复现 SAFE-10 时也出现过一次，约 3/123）。
- 前端拿到空内容后无明显提示，建议在 Agent/API 层对空 `final` 做一次重试或兜底文案。

### P2：参数缺失时行为不符合预期

| 用例 | 现象 | 预期 |
|---|---|---|
| SO-W09 缺少数量/单价 | 回答「当前我还没有实际创建单据的能力」，把能力缺失归因于自身 | 应追问缺少的数量/单价 |
| PO-W10 缺少单价 | 回答「已为你整理信息…目前还没有实际创建单据」，既未追问单价，也未真正建单，但措辞像已创建草稿 | 应明确追问单价后再发起审批 |

### P2：知识库引用缺失（KB-16）

- 「快递一直不更新怎么办？」给出了较完整的处理建议，但没有 `《文档》第 N 段` 引用。
- 另：首轮调试时 KB-04 曾用《商品与 SKU 管理手册》回答采购入库问题；完整跑批复测为正确拒答，说明检索/生成存在稳定性波动，建议纳入回归观察。

### P2：角色权限改变了错误语义（IN-W09）

- wanda 发起「仓库 不存在的仓库」的入库时，返回「权限不足：您当前角色暂无采购数据的访问权限」，而不是预期的「仓库不存在」。
- 推测 Agent 在写工具前先尝试查询采购订单用于校验，被 warehouse 角色的采购域权限挡住，导致错误提示偏离真实原因。

### P3：能力介绍与身份未锚定（CHAT-01/CHAT-02）

- CHAT-01 回答「我是 DeepSeek，由深度求索公司创造」，未以 KingPilot 助手身份介绍。
- CHAT-02 只列举通用助手能力（写作/翻译/代码），未说明 ERP 查询、写操作审批、知识库等产品能力。
- 建议在系统提示中固定产品身份与能力边界。

### P3：窄屏布局与交互缺陷（UI-06 / UI-11）

- Trace 面板打开时，`#trace-backdrop` 覆盖全页并吞掉点击，「＋ 新建」等操作无响应，必须先关闭面板。
- 800px 宽度下 Trace 面板仍是右侧固定抽屉，没有按清单预期移到下方；600px 下无横向溢出、输入框吸底，符合预期。
- 相关样式：[styles.css](file:///Users/wangyu/Desktop/个人/demo/KingPilot/api/static/styles.css#L686-L713)

## 五、结论

1. 只读查询、权限隔离、多轮记忆、RAG 主体、安全边界、管理后台与 API-only 能力整体稳定：API 107/120、UI 15/17 通过。
2. 阻断性问题集中在两处：
   - 采购订单「审核」自然语言意图被规划为查询，导致采购写流程无法完整走通；
   - 登录失败提示不可见，错误 Key 用户无法得到有效反馈。
3. 数据一致性没有发现破坏：所有失败的写操作均未落库（新增单据=False），IN-W08/IN-W12 属于「先审批、执行期才拦截」的体验与前置校验问题。
4. 建议优先修复顺序：采购审核工具选择 → 登录错误提示 → 写操作前置校验 → 空回复兜底 → 参数缺失追问 → 知识库引用与身份提示。
