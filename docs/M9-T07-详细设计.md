## 1. 任务回顾

### 1.1 目标

把线上失败请求变成可回归的评测用例：

- 运营/管理员从某条 Trace 标记 Badcase
- 记录原因、期望工具、期望行为
- 问题与说明统一脱敏 + DLP 兜底
- 导出为版本化评测集 JSON，供 M8 离线评测/发布门禁使用
- 同一 Trace 不重复建单；同一用例不重复入集

### 1.2 本卡做

| 能力 | 说明 |
|------|------|
| Badcase 模型 | `BadcaseRecord`：trace_id / 问题 / 期望 / 原因 / 状态 |
| 持久化 | 一单一个 JSON，原子写 + 0600 |
| 标记 | 从 Trace 提取问题，脱敏后建单 |
| 导出 | 合并进 `evals/datasets/{version}/tool_selection.json` |
| 去重 | 同 Trace 幂等；同问题+期望工具不入集 |
| API | 标记 / 列表 / 详情 / 导出 |
| 审计 | `badcase.marked` / `badcase.exported` |
| 测试 | 脱敏、去重、数据集校验、权限、幂等 |

### 1.3 本卡明确不做

- **不做 Badcase UI**：控制台仍只有对话/会话/Trace；工作台 UI 后续
- **不做用户点赞/点踩采集**：只支持人工标记
- **不做自动归因**：原因由运营填写，不自动判断是规划/参数/知识问题
- **不做多数据集类型**：只导出到 M8 的 `tool_selection` 数据集
- **不做删除/回滚**：已导出的评测用例不在本卡删除
- **不做跨仓同步**：导出到配置目录，不自动提 PR/commit

### 1.4 验收标准（来自任务卡）

- [ ] 一键生成用例并能被 `offline_eval` 跑通
- [ ] 未脱敏/含 PII 的样本被拒绝入库
- [ ] 同一 trace 不重复入集

## 3. 关键设计决策（需审批）

### D1. 仅 `admin` / `manager` 可操作

- 标记、列表、详情、导出全部要求 `role in {"admin","manager"}`
- 理由：Badcase 会影响发布门禁；不能让普通用户随意污染评测集
- 普通用户 403 `forbidden`

### D2. 一条 Trace 只建一张 Badcase

- `mark(trace_id)` 幂等：已存在则直接返回原记录（不重复建文件）
- 不允许多条记录指向同一 trace
- 理由：同一请求重复标记会产生重复评测用例

### D3. 必须显式给出 `expected_tool`

- 请求字段 `expected_tool: string | null` 必填：
  - 字符串 = 期望调用该工具
  - `null` = 期望纯聊天、不调用工具
- 不提供默认值，避免“漏填被当成纯聊天”污染数据集
- `expected_behavior` 为可选说明（用于人工阅读；M8 判定仍看 `expected_tool`）

### D4. 入库前双重脱敏

1. `redact_text` 掩码问题、原因、期望行为
2. `DlpScanner` 再扫一遍；仍命中 → 拒绝入库

- 拒绝码：`badcase_sensitive`（422）
- 不把原始 trace、工具结果、最终答复写入 Badcase 或数据集
- 只保留“问题 + 期望工具 + 分类 + 原因/期望行为”

### D5. 一单一个 JSON，0600

```
{badcase_store_dir}/{badcase_id}.json
```

- 原子写：`.tmp` → `replace`
- 目录 0700、文件 0600
- `badcase_id` 白名单校验
- 读取 fail-closed；列表 fail-soft（坏文件跳过）

### D6. 导出到版本化 M8 数据集，原子合并

```
{eval_dataset_dir}/{dataset_version}/tool_selection.json
```

- 默认 `dataset_version=v1`（与现有固定集同版本）
- 文件不存在 → 新建 `{"version": version, "cases": []}`
- 文件存在 → 先 `load_dataset` 校验，再追加，再原子写
- 写入后再次 `load_dataset` 自检（fail-closed）
- 保留原始 `cases` 的其他字段，不因重写丢失元数据

### D7. 去重与 ID 唯一

- 同 Trace：幂等返回原记录
- 导出时按 `(question, expected_tool)` 去重：
  - 已存在 → 409 `badcase_duplicate`
- 用例 ID：`BC-{badcase_id[:8]}`；冲突时追加 `-2`、`-3`
- 导出后记录状态 `exported`，重复导出幂等返回

### D8. 数据集只追加，不删除/回滚

- 本卡不提供删除接口
- 误标可通过后续人工编辑数据集修正
- 理由：评测集是发布门禁输入，运行时删除风险高

### D9. 审计事件

新增：

- `badcase.marked`
- `badcase.exported`

审计 detail 只放 `badcase_id / trace_id / dataset_version / question_id`，不放问题原文与原因。

### D10. 本卡只做 API，不做工作台 UI

- 控制台（T03）暂不加 Badcase 按钮
- 后续工作台 UI 直接消费本卡 API

## 4. 数据模型

### 4.1 `models/badcase.py`

```python
BadcaseStatus = Literal["marked", "exported"]


class BadcaseRecord(KingPilotBaseModel):
    badcase_id: str = Field(default_factory=lambda: uuid4().hex)
    trace_id: str
    question: str = Field(max_length=1000)
    expected_tool: str | None
    expected_behavior: str = Field(default="", max_length=1000)
    category: str = Field(default="badcase", max_length=64)
    reason: str = Field(max_length=500)
    status: BadcaseStatus = "marked"
    created_by: str
    created_at: datetime
    exported_dataset: str = ""  # 相对路径或版本
    exported_question_id: str = ""
    exported_at: datetime | None = None
```

## 5. 标记流程

```text
POST /v1/badcases
  → 校验 admin/manager
  → TraceStore.load(trace_id)（不存在 404）
  → question = redact_text(trace.user_input)[:1000]
  → reason / expected_behavior = redact_text(...)
  → DLP 扫描三段文本；命中 → 422 badcase_sensitive
  → expected_tool 校验（None 或 Registry 已知工具）
  → 同 trace 已有记录？返回原记录
  → 保存 BadcaseRecord(status=marked)
  → 审计 badcase.marked
```

问题为空（如 trace 没有 user_input）→ 422 `badcase_invalid`。

---

## 6. 导出流程

```text
POST /v1/badcases/{id}/export {"dataset_version": "v1"}
  → 校验 admin/manager
  → load BadcaseRecord
  → status=exported → 幂等返回
  → 定位 {eval_dataset_dir}/{version}/tool_selection.json
  → 文件存在：load_dataset 校验；不存在：新建
  → 按 (question, expected_tool) 去重；命中 → 409 badcase_duplicate
  → 生成唯一 question_id
  → 追加 case：
      {
        "question_id": "BC-...",
        "question": record.question,
        "expected_tool": record.expected_tool,
        "category": record.category,
        "expected_behavior": record.expected_behavior,
        "source": "badcase:<badcase_id>"
      }
  → 原子写
  → 再 load_dataset 自检
  → 更新记录 exported + dataset/version/question_id
  → 审计 badcase.exported
```

- `expected_tool` 必须在当前 Registry 中存在（或 null）；否则标记阶段已拒绝
- Dataset version 白名单：`^[A-Za-z0-9][A-Za-z0-9._-]{0,31}$`，防路径穿越
- 既有文件的 `version` 与目标目录版本不一致 → 409 `badcase_dataset_conflict`

## 7. API

### 7.1 `POST /v1/badcases`

请求：

```json
{
  "trace_id": "…",
  "expected_tool": "kingdee_query_customer",
  "reason": "应查客户却查了订单",
  "category": "badcase",
  "expected_behavior": "应先按名称换客户编码再查订单"
}
```

- `expected_tool` 必填，可为 `null`
- `reason` 必填，1~500 字符
- 响应 200：`BadcaseView`

### 7.2 `GET /v1/badcases?status=marked&limit=50`

- `status` 可选 `marked/exported`
- `limit` 1~200，按创建时间倒序
- 仅 admin/manager

### 7.3 `GET /v1/badcases/{badcase_id}`

- 不存在 → 404 `badcase_not_found`

### 7.4 `POST /v1/badcases/{badcase_id}/export`

请求：

```json
{"dataset_version": "v1"}
```

- 默认 `v1`
- 成功返回更新后的 `BadcaseView`
- 重复导出幂等
- 重复用例 → 409 `badcase_duplicate`

### 7.5 `BadcaseView`

```json
{
  "badcase_id": "…",
  "trace_id": "…",
  "question": "查一下客户 CUS001 的订单",
  "expected_tool": "kingdee_query_customer",
  "expected_behavior": "先换客户编码",
  "category": "badcase",
  "reason": "应查客户却查了订单",
  "status": "exported",
  "created_by": "admin",
  "created_at": "…",
  "exported_dataset": "v1/tool_selection.json",
  "exported_question_id": "BC-…",
  "exported_at": "…"
}
```

### 7.6 错误码

| code | HTTP | 场景 |
|------|------|------|
| `badcase_not_found` | 404 | 记录不存在 |
| `badcase_invalid` | 422 | 问题为空/字段非法 |
| `badcase_sensitive` | 422 | 脱敏后仍触发 DLP |
| `badcase_unknown_tool` | 422 | expected_tool 未注册 |
| `badcase_duplicate` | 409 | 同问题+期望工具已存在 |
| `badcase_dataset_conflict` | 409 | 数据集版本冲突/结构非法 |
| `badcase_store_failed` | 500 | 持久化/写入失败 |
| `forbidden` | 403 | 非 admin/manager |

## 12. 风险与边界

| 风险 | 处理 |
|------|------|
| 运行时写仓库评测集 | 路径可配置；生产改指外部目录 |
| 多进程并发写数据集 | 单 worker + 原子写；跨进程锁归 M9-T11 |
| 数据集手工改坏 | `load_dataset` fail-closed，导出前校验 |
| 问题脱敏后语义变化 | 可接受；宁可变脱敏也不泄露 PII |
| Badcase 只覆盖工具选择 | 本卡与 M8 判定口径一致；响应质量评测后续扩展 |
| 无删除/回滚 | 设计边界；误标人工修数据集 |
| 同一问题不同期望 | 去重键含 expected_tool，允许并存 |
| 审计泄露原文 | detail 只放 ID/版本/question_id |

## 13. 学习指引

1. **为什么 Badcase 要脱敏后再入集**：评测集会被多人读取、长期保存。
2. **为什么 expected_tool 必须显式**：null 与“漏填”语义完全不同。
3. **为什么导出前要 load_dataset**：防止把坏数据合并进发布门禁输入。
4. **为什么写后还要自检**：原子写只保证文件完整，不保证 schema 合法。
5. **去重键为什么含 expected_tool**：同一问题可能有不同期望。
6. **为什么只有 admin/manager**：评测集是发布门禁输入。
7. **为什么不做删除**：append-only 与可追溯优先。
8. **为什么保留原始 cases 字段**：避免重写丢失人工维护的元数据。
