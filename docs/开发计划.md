## 一、文档使用说明与标记规则

### 1.1 协作工作流（铁律）

沿用既定协作方式，**逐个拆分、逐个审批、逐个落地**：

```
1. 认领任务     → 从本文档任务清单中取「下一个未完成任务」（一次只允许一个进行中）
2. 出详细设计   → 为该任务单独出小任务级开发计划（含分步实现 + 带注释的关键代码 + 学习指引）
3. 审批         → 用户确认通过后才开始写代码
4. 实现与自测   → 按 lint / typecheck / test 全绿标准完成
5. 验收         → 达成任务卡上写明的验收标准
6. 标记与提交   → 回到本文档勾选任务、填写完成日期与 commit，再提交 git
7. 进入下一任务 → 回到第 1 步
```

### 1.2 任务状态标记

| 标记 | 含义 | 写法 |
|------|------|------|
| ⬜ 未开始 | 默认状态 | `- [ ] **M1-T01** ...` |
| 🔄 进行中 | 已认领、正在做 | `- [ ] 🔄 **M1-T01** ...`（在任务前加 🔄） |
| ✅ 已完成 | 验收通过 | `- [x] ✅ **M1-T01** ...（2026-10-15 @a1b2c3d）` |
| ⏸️ 暂停 | 被外部依赖卡住 | 任务后追加 `⏸️ 原因：xxx` |
| ❌ 已废弃 | 设计变更不再需要 | 任务后追加 `❌ 废弃：原因 + 替代任务号` |

**勾选必须同时满足**：代码合入 + 测试全绿 + 验收标准达成 + 完成日期 + commit 短哈希。只写完代码没验收的，一律保持 🔄。

### 1.3 完成定义（DoD，全局通用）

一个任务只有同时满足以下条件才算「完成」：

1. 代码通过 `ruff check` + `ruff format --check` + `mypy` 无错误
2. 新增/修改逻辑有对应单测，模块覆盖率达标（见 3.7 测试规范）
3. 任务卡上的验收标准逐条核验通过
4. 本文档勾选并更新进度总览看板
5. 按提交规范形成 commit（一个任务至少一个独立 commit）

### 1.4 防重复机制

- **认领前先查本文档**：任何代码开工前，先在任务清单确认该任务状态不是 ✅
- **一次一个任务**：同时最多一个 🔄，避免并行导致的范围漂移
- **任务 ID 全局唯一**：`M{模块号}-T{两位序号}`，沟通、分支名、commit 一律引用任务 ID
- **冲突以本文档为准**：口头/聊天里说过要做的，没进本文档就不算数；要新增工作项必须先加任务卡
- **定期对账**：每完成一个模块，核对一次 git log 与任务清单，补漏纠偏

## 三、全局编程规范（企业级）

> 适用所有模块。模块专属规范见第四章各模块小节，模块规范与全局规范冲突时，**以更严格者为准**。

### 3.1 技术栈与版本基线

| 组件 | 选型 | 版本要求 |
|------|------|----------|
| 语言 | Python | 3.11+（启用 `asyncio.TaskGroup` 等特性） |
| HTTP | httpx（异步） | 最新稳定版 |
| 数据模型 | Pydantic v2 | v2.x，禁止用 v1 API |
| 配置 | pydantic-settings | — |
| 日志 | loguru | — |
| 测试 | pytest + pytest-asyncio + respx | — |
| 质量工具 | ruff / mypy / pre-commit / pip-audit | ruff 承担 lint + format |

依赖必须锁定（`pyproject.toml` + lock）。**工具链已定：uv**（锁定文件 `uv.lock`，解释器 `.python-version=3.12`，安装 `uv sync --extra dev`）；新增依赖需在任务卡中说明理由。

### 3.2 代码规范

**命名**

| 对象 | 规范 | 示例 |
|------|------|------|
| 包/模块 | 小写下划线 | `kingdee/client.py` |
| 类 | PascalCase | `KingdeeClient` |
| 函数/变量 | snake_case | `execute_bill_query()` |
| 常量 | UPPER_SNAKE | `RISK_RULES` |
| 私有成员 | 前缀 `_` | `_refresh_token()` |
| 异常类 | `Error`/`Exception` 结尾 | `KingdeeAuthError` |
| 布尔变量/属性 | `is_`/`has_`/`need_` 前缀 | `need_confirmation` |

**结构与复杂度**

- 函数 ≤ 50 行；单文件 ≤ 400 行；超出必须拆分（对应 component-split 思路）
- 圈复杂度 ≤ 10，超过用策略表/字典分发重构
- 禁止魔法数字与魔法字符串：一律进 `config/` 常量或 `Enum`/`Literal`
- 导入顺序三段式：标准库 → 第三方 → 本项目，组间空行（ruff isort 规则强制）
- 禁止 `import *`；禁止相对导入跨包

**异步**

- 所有 I/O（HTTP/DB/Redis）一律 `async def`，同步 I/O 禁止出现在 async 路径
- 并发调用统一 `asyncio.gather(..., return_exceptions=False)` 并显式超时
- 长任务必须有取消与超时保护，禁止裸 `await` 无超时的外部调用

**注释与文档字符串**

- 注释解释 **Why**（为什么这么做/踩过什么坑），不复述 What
- 公共模块/类/函数必须有 Google 风格 docstring：

```python
async def query_orders(self, filter_string: str, page_size: int = 100) -> OrderListResult:
    """执行销售订单查询（金蝶 ExecuteBillQuery）。

    Args:
        filter_string: 过滤条件，必须先通过 Guard 2 AST 校验。
        page_size: 分页大小，硬上限 10000（Guard 4）。

    Returns:
        订单列表结果，含总行数与分页游标。

    Raises:
        GuardBlockedError: 过滤条件含危险模式或字段不在白名单。
        KingdeeAPIError: 金蝶侧返回非成功状态码。
    """
```

### 3.3 类型与数据模型规范

- 全量类型注解，`mypy --strict` 零错误是合入门禁
- **边界用 Pydantic**（API 请求/响应、配置、LLM Tool Call JSON）；**内部值对象用 `@dataclass(frozen=True)`**（不可变，防意外篡改）
- 闭集用 `Literal` 或 `Enum`：如 `tool_type: Literal["query", "write", "action"]`
- 所有模型集中在 `models/`，按领域分文件，禁止模型定义散落在业务代码里
- Pydantic 模型显式声明 `model_config = ConfigDict(extra="forbid")`，边界输入拒绝未知字段（fail-closed）

### 3.4 异常处理规范

- 统一异常层次，根为 `KingPilotError`，按模块派生：

```
KingPilotError
├── KingdeeError            # 金蝶适配层
│   ├── KingdeeAuthError
│   ├── KingdeeRateLimitError
│   └── KingdeeAPIError
├── SafetyError             # 安全护栏（GuardBlockedError / PermissionDeniedError ...）
├── LLMError                # LLM 不可用/超时/输出不合法
├── SagaError               # 编排与补偿失败
└── LedgerError             # 溯源账本写入/校验失败
```

- 禁止裸 `except:`，禁止 `except Exception` 吞掉不重抛；能处理则处理并留痕，不能处理则带上下文上抛
- 重试只允许出现在 `kingdee/client.py` 一处，且**仅限幂等方法**（GET/查询）；写操作重试必须走幂等层（M5）
- 异常消息必须携带可定位上下文（formId、操作名），trace_id 由日志层统一注入

### 3.5 日志规范

- 只用 loguru，**禁止 print**；第三方库标准 logging 统一拦截转 loguru
- 每条业务日志必带 `trace_id`（contextvars 注入，见 M6-T03）
- 级别语义：

| 级别 | 使用场景 |
|------|----------|
| DEBUG | 开发调试细节（LLM 原始报文、中间状态） |
| INFO | 关键业务事件（Tool 执行、Saga 状态迁移、HITL 确认结果） |
| WARNING | 可恢复异常（限流退避、降级触发、幻觉纠错成功） |
| ERROR | 操作失败（API 报错、补偿失败、Guard 拦截后的审计留痕） |
| CRITICAL | 系统级不可用（账本校验失败、数据完整性受损） |

- **脱敏红线**：Token、密码、客户敏感字段（手机号/身份证/金额明细按 M7 分级）一律不得原文入日志
- loguru 占位符风格：`logger.info("tool executed: {} form={}", tool_name, form_id)`，禁止 f-string 拼接（保留惰性求值）

### 3.6 配置与密钥规范

- 配置统一走 `config/settings.py`（pydantic-settings），`.env` 本地加载，`Settings()` 进程内单例
- `.gitignore` 从 Day 1 包含 `.env`；仓库只提交 `.env.example`（占位值）
- 环境分层：`dev / test / prod`，同一份 Settings 用前缀区分（如 `KINGPILOT_ENV`）
- **密钥永不硬编码、永不入 git、永不出现在异常栈消息里**
- 规则表与逻辑分离：风险规则、权限规则、告警规则、模型路由全部放 `config/` 独立文件（对应方案目录结构），改规则不改代码

### 3.7 测试规范

- 命名：`test_<被测单元>_<场景>_<预期结果>`，如 `test_guard_sql_injection_blocked`
- 结构：AAA（Arrange-Act-Assert），一个测试函数只验证一个行为
- **单测零网络**：金蝶 API 用 respx mock，LLM 用 fake provider；真实沙箱调用只出现在标记为集成的测试（`-m integration`，手动/CI 定时跑）
- 公共测试数据放 `tests/conftest.py` fixture，禁止测试间共享可变状态
- 覆盖率门禁：全局 ≥ 80%；`safety/`、`ledger/` 模块 ≥ 90%（安全与溯源不允许低覆盖）
- 每个任务卡的验收标准里必须包含「关键路径有用例覆盖」

### 3.8 Git 与提交规范

- Conventional Commits，格式：`<type>(<scope>): <subject>`，subject 用中文说清「做了什么」

| type | 用途 |
|------|------|
| feat | 新功能 |
| fix | 缺陷修复 |
| refactor | 重构（不改行为） |
| test | 测试补充 |
| docs | 仅文档 |
| chore | 工具链/配置 |

- 分支命名：`feature/M1-T03-kingdee-auth`（任务 ID 进分支名，可追溯）
- 一个任务一个分支；合入前 self-review diff + 本地全绿（lint/typecheck/test）
- 禁止 force push 主干；禁止跳过 pre-commit 钩子提交

### 3.9 安全编码规范

- 所有外部输入（用户输入、LLM 输出、金蝶返回）在边界做 Pydantic 校验，**默认拒绝**（extra="forbid"）
- FilterString 类输入执行「黑名单模式 + 白名单字段」双重校验（Guard 2 规范，方案 §5.1 支柱二）
- 依赖锁定 + `pip-audit` 定期扫描；升级依赖是独立任务，不夹带
- 最小权限：任何模块只拿它需要的凭证与数据域，禁止「先全开再收」
- 日志/异常消息出口统一过脱敏（M7 落地前，先手工遵守红线清单）

### 3.10 工具链与质量门禁

| 命令 | 作用 |
|------|------|
| `make lint` | ruff check + format 校验 |
| `make typecheck` | mypy --strict |
| `make test` | pytest（不含集成） |
| `make test-integration` | pytest -m integration（真实沙箱） |
| `make cov` | 覆盖率报告 |
| `make audit` | pip-audit 依赖扫描 |
| `make eval` | Tool 选对率评测（真 LLM，开发辅助非门禁；`ROUTE=` 覆盖 .env 路由） |

- pre-commit 钩子：ruff（lint + format）+ 基础大文件/私有信息检查（**detect-secrets 基线机制**，工具/版本锁定在 `.pre-commit-config.yaml`）
- **任务完成 = 本地 `make lint typecheck test` 三绿**，缺一不可

### M1 金蝶适配层（Step 1：K3Cloud 协议链路调通）

**目标**：硬编码 1 个 Tool 调通 K3Cloud 协议链路，建好企业级 HTTP 客户端底座。

> 数据源策略（2026-10-16 决策）：个人开发者暂无真实沙箱凭证（T01 挂起），改用**本地契约仿真沙箱**（`sandbox/`，FastAPI 实现）作为数据源。仿真端严格按官方文档/SDK 协议形状实现；真实凭证到位后仅改 `.env` 5 行，同一套 integration 测试直连真金蝶复验，零代码切换。

**验收标准**（方案 §八）：integration 测试经仿真沙箱返回符合协议的数据；client 层单测（respx）覆盖超时/重试/限流路径。

**前置依赖**：M0 ✅

**方案文档引用**：§5.1 支柱三/四、§3.1 金蝶 API 参数结构、§七 kingdee/ 目录。

**模块规范**：

1. 所有金蝶调用**必须**走 `KingdeeClient`，禁止业务代码直接出现 httpx 调用
2. client 方法返回 Pydantic 模型（`models/kingdee.py`），不返回裸 dict
3. 每次请求显式超时；限流（信号量/令牌桶）内置；仅幂等方法自动重试（指数退避 + 抖动）
4. 认证凭证（app_id/app_secret/token）永不入日志与异常消息
5. `endpoints/` 按 formId 组织端点描述，查询字段白名单在这里维护（为 M4 Guard 2 供数）
6. 仿真沙箱（`sandbox/`）只实现官方文档/SDK 有明确依据的协议行为；推断行为必须标注 `# INFERRED:` 注释，真环境联调时逐条核对

**任务清单**：

**模块小结（M1-T07，踩坑记录与协议知识沉淀）**：

1. **协议知识沉淀**（对接方无权修正的事实）：
   - 方案 §3.1 写的 `PageSize/PageIndex/SortString` 与真协议不符，真协议是 `Limit`（0=不限）/`StartRow`（行偏移）/`OrderString`，且 `FormId` 在 `data` 内层（T02 决策 D1 按真协议实现）
   - 失败响应 **HTTP 同样是 200**，错误包在二维数组 `[[{"Result":{"ResponseStatus":{...}}}]]` 里——必须解析返回体判 `IsSuccess`，靠状态码判错会漏掉全部业务错误
   - 官方拼写 `SuccessEntitys`（应为 Entities）必须原样保留，否则反序列化失败
   - `LoginBySign` 签名 = `[账套,用户,应用ID,密钥,时间戳]` 字符串序排序拼接 → SHA256 hex 小写；密钥只做本地签名盐、永不出网
2. **工程教训**（本项目实测踩到，后续模块规避）：
   - **测试与实现共用常量 = 同义反复**：T06a 仿真端路径写成斜杠拼接，单测全绿（替身测试 import 同一常量）；T06b 真 HTTP 链路一发即 404。教训：契约替身必须有一次「第三方视角」的全链路验收才算数
   - **detect-secrets 误报**：pragma 必须与疑似字面量同行（ruff format 拆行会让标注错位失效），解法是字面量提模块常量
   - **respx 即时返回掩盖并发分支**：mock 不挂起 → 协程实际串行执行，锁内二次检查（防抖核心分支）从未执行；需要挂起点（`sleep(0)` 让出）才能制造真实并发窗口
   - mypy strict 三坑：monkeypatch 方法赋值（`method-assign`）改用构造注入；lambda 默认参数无法推断类型改用工厂函数；无 `__init__.py` 目录会被双重推断模块名（`scripts/` 补文件）
   - ruff B017 禁止盲捕 `Exception`，测试断言具体异常类型
   - 非限流 4xx 归一化为确定性失败（`_Verdict.HTTP_ERROR`）不重试、不解析响应体——由「400 空响应体 JSONDecodeError」实测引出
3. **INFERRED 待核对清单**（真凭证到位后联调时逐条核对，全部源自 `# INFERRED:` 标注）：
   - 会话 TTL（现取保守 25 分钟）、会话失效报错原文关键词（"会话信息丢失，请重新登录"）
   - 错误信封各 MsgCode 取值（仿真端用的 4/5/9/10/11/12/13 为常见约定值）
   - `SAL_ORDER` 中 8 个标 INFERRED 的字段拼写；`FCloseStatus` 值域（A/B）
   - `TopRowCount` 统计语义（仿真端未实现，显式报错）

**模块小结（M2-T06，决策回顾与工程教训沉淀）**：

1. **核心设计决策**（T01~T05 贯穿，M3+ 继续遵守）：
   - **LLM 永远不接触 FilterString 原文**（T03 核心主张）：LLM 只产结构化参数（Pydantic 校验 fail-closed），FilterString 由端点层组装且条件字段全部落在 `filterable_fields` 白名单内——注入面在编译期消除，而非运行期拦截
   - **Schema 单一真源**：Tool 给 LLM 的声明 = `params_model.model_json_schema()` 自动生成，声明与校验永不漂移（改模型即改 schema，零同步成本）
   - **模型路由即配置**：`MODEL_REGISTRY` 唯一真源，本地 Ollama 千问 / DeepSeek 切换只改 `.env` 一行路由名，零代码改动（T02 实测两模型 function calling 均可用）
   - **异常四分类定降级边界**：`LLMUnavailableError` 是降级的唯一触发点；`LLMResponseError`（响应不合法）属确定性错误不降级——防止「坏响应反复重试」污染调用预算
2. **工程教训**（本模块实测踩到，后续模块规避）：
   - **pydantic-settings 的 env_file 独立于 os.environ**：conftest 清空 `KINGPILOT_*` 环境变量挡不住 `.env` 加载机制——`.env` 配了 ollama 路由后，17 个单测经 `Settings()` 构造读到该值打向本地 Ollama 全红。解法：测试中 `Settings(_env_file=None, ...)` 构造级禁读（T03 期间修复）
   - **评测驱动开发闭环有效**：T05 设计问题集时发现 `SalesOrderParams` 缺 `bill_no/order_date`（最典型问法「查 SO000008」「查 3 月的订单」参数放不下）——评测不只是验收，是需求发现工具（D6 顺路补字段，约 20 行）
   - **评测口径的纪律**：ERROR（网络抖动）不计分母但必须显性展示——不让基础设施失败污染模型能力指标，也不让失败隐形；「参数陷阱」题（工具对、参数未必放得下）保留为参数通过率观察样本，不扣选对率
   - **temperature 不进请求体 = 指标不可复现**：DeepSeek 默认 1.0 时选对率每次跑都会抖，透传 `llm_temperature`（默认 0 贪心解码）是评测可信的前提（T05 D4）
   - **契约替身支持新端点 = 注册表加一项**：T04 沙箱从「SAL_Order 专用」重构为 per-FormId 注册表（query_engine.py 从 app.py 拆出），加 STK_Inventory 只动了数据集 + 注册一行——表驱动让扩展成本趋近于零
3. **验收指标实际达成**：
   - Tool 选对率 **100.0%**（31/31，DeepSeek chat_default，阈值 >90%；含 4 个参数陷阱题 params 全 ok）

### M7 数据安全与成本治理（Step 7：合规可上生产）

**目标**：数据分级脱敏 + DLP 出域扫描 + 模型路由/语义缓存/预算熔断。

**验收标准**（方案 §八）：出域扫描零命中（敏感数据不出边界）。

**前置依赖**：M6 ✅

**方案文档引用**：§5.4 支柱十一（脱敏/DLP）、支柱十二（注册中心/可配置路由/语义缓存/预算熔断）。

**模块规范**：

1. 脱敏在**统一出口**执行（响应生成与日志两处），禁止各模块自行脱敏造成遗漏
2. 数据分级（公开/内部/敏感/高敏）与字段映射配置化，脱敏算法按级别选择（掩码/哈希/拒出）
3. DLP 扫描在响应发送前执行，命中即阻断并审计（fail-closed）
4. 成本核算到单次请求（模型/档位/token 单价），`ROUTING_CONFIG` 热切换不改代码
5. 预算熔断触发后自动降档（HIGH→MID→ECONOMY），全档超限则限流并告警
