## 1. 任务回顾

### 1.1 目标

把 M9-T04 的「审批单」接到主循环与写事务上：

- 主循环遇到 `dual_approve` 不再同步等待，而是创建审批单并返回
- `/v1/chat` 返回 **202 + approval_id**
- 审批单被两人通过后，按持久化动作恢复执行
- 执行复用 M5 的幂等键、Saga、账本与死信
- 进程重启后可恢复：执行状态落盘，已成功的不重复执行
- CLI 保持现有同步确认，行为零变化

### 1.2 本卡做

| 能力 | 说明 |
|------|------|
| `ApprovalGateway` | HITL 双人复核 → 创建审批单 |
| 主循环 202 | `AgentResponse`/`ChatResponse` 增加审批字段 |
| 审批执行器 | `ApprovalExecutor`：加载 trace → WriteCoordinator → 落账 |
| 执行状态 | `not_started → running → succeeded / failed` |
| 恢复 | 审批通过自动执行；失败/中断可手动重试 |
| API | 审批视图增加执行状态；新增手动执行入口 |
| 审计 | execution_started / executed / execution_failed |
| 测试 | Gateway、202、执行一次、重试、重启、失败、账本恢复 |

### 1.3 本卡明确不做

- **不做真实写工具**：当前 Registry 只有查询工具；执行器用 `ToolExecutor` 协议注入，测试用 FakeExecutor
- **不做批量写审批**：一张审批单只对应一个写调用；多调用 fail-closed
- **不做审批中心 UI**：控制台仍只有对话/会话/Trace；审批 UI 归后续
- **不做通知/轮询**：执行结果通过审批详情 API 查看；会话回写与提醒归 T06
- **不做跨进程执行锁**：单 worker；多实例归 M9-T11
- **不做金蝶侧幂等键透传**：本地幂等 + 账本恢复；真实写接口落地时补 vendor 幂等键

### 1.4 验收标准（来自任务卡）

- [ ] 审批通过后写操作恰好执行一次（并发/重试/重启均不重复）
- [ ] 拒绝或过期不执行
- [ ] Trace 串联「提交 → 审批 → 执行」全链路

| 现有能力 | 现状 | T05 需要 |
|----------|------|----------|

## 3. 关键设计决策（需审批）

### D1. 只接管 `dual_approve`，`confirm` 保持原语义

- API 模式 `dual_approve` → 创建审批单
- API 模式 `confirm` 仍由 `DenyConfirmationIO` 拒绝（T01 边界）
- CLI 不注入网关 → 继续两次终端确认
- 理由：任务卡针对「双人复核」；`confirm` 的单人确认不应变成两个审批人

### D2. 一张审批单只对应一个写调用

- `SafetyLayer.review` 的 plan 若包含多个调用且命中 `dual_approve`：
  - 网关直接抛 `ApprovalError(code="approval_conflict")`
  - 消息：「一次审批仅支持单个写操作」
- 理由：T04 的 `PendingAction` 是单工具单参数；批量审批需要原子性和部分失败语义，不能假装支持

### D3. 主循环返回「审批待处理」，不执行

`AgentCore` 在 `_phase2_guard` 得到 `approval_pending=True` 时：

- 不发 Phase 3/4，不调用写工具
- `trace.approval_id = approval_id`
- `final_response = "已提交审批（…），双人复核通过后自动执行。"`
- 写入记忆（用户看到提交结果）
- 返回 `AgentResponse(approval_pending=True, approval_id=...)`

`/v1/chat` 看到 `approval_pending` 时把 HTTP 状态改为 **202**。

### D4. `final`/SSE 语义

- `/v1/chat/stream` 的 HTTP 状态仍是 200（流已开始）
- `final` 事件增加 `approval_pending` / `approval_id`
- 客户端必须解析事件，不能只看 HTTP 状态

### D5. 审批通过自动执行；另留手动恢复入口

- `POST /v1/approvals/{id}/approve`：
  - 投票后若 `status=approved` → 立即调用 `ApprovalExecution.execute`
  - 执行失败不回滚审批状态；返回 `execution_status=failed`
- 新增 `POST /v1/approvals/{id}/execute`：
  - admin/manager 可调用
  - 用于进程重启后恢复 `approved + not_started/running/failed`
- 不在启动时自动扫描执行：避免服务重启时静默产生写操作

### D6. 执行状态落盘在审批单上

`PendingAction` 增加：

```python
ApprovalExecutionStatus = Literal["not_started", "running", "succeeded", "failed"]

execution_status: ApprovalExecutionStatus = "not_started"
execution_error: str = ""
execution_result: dict[str, Any] = {}
executed_at: datetime | None = None
```

- `approved` 是审批结论；`execution_status` 是执行结论，两者独立
- 旧 T04 文件没有这些字段，Pydantic 默认值自动兼容

### D7. 执行幂等：状态机 + 账本双重检查

1. 进程内按 `approval_id` 加锁（`WeakValueDictionary`）
2. `execution_status=succeeded` → 直接返回
3. `running`（上次中断）→ 先查账本：同 trace/form/business/action 已有成功记录 → 标记 succeeded，不再调用工具
4. 无成功记录 → 继续执行；`saga_id=approval_id` 确定性，Saga 幂等键固定
5. 失败 → `failed`，允许手动重试

**边界**：Kingdee 写入与本地账本不是分布式事务。本地保证正常重试/重启不重复；真实写接口必须透传幂等键，才能覆盖「写成功但账本未落」的崩溃窗口。

### D8. Trace 必须存在且归属匹配

执行前：

```python
trace = trace_store.load(action.trace_id)
if trace.user_id != action.requester_id:
    fail("Trace 归属不符")
```

- 原请求的 Trace 在返回 202 前已落盘
- Trace 缺失/归属不符 → `execution_status=failed`，零写入

### D9. 复用 WriteCoordinator，单步 Saga

```python
operation = WriteOperation(
    SagaStep(
        step_id=action.approval_id,
        tool_name=action.tool_name,
        arguments=action.arguments,
        action=action.write_action,
    ),
    form_id=action.form_id,
    business_key=action.business_key,
)
result = await writer.execute(
    trace, [operation], executor, snapshots, saga_id=action.approval_id
)
```

- `write_action` 新增到 `PendingAction`（save/edit/submit/audit/unaudit/delete）
- `SnapshotProvider` 与 `ToolExecutor` 通过协议注入
- 当前默认 `RegistryToolExecutor` 只适用于未来实现统一 `execute` 的写工具；没有写工具时 fail-closed
- 默认 `NoopSnapshotProvider`；`edit/delete/unaudit` 需要真实快照时执行失败（由 WriteCoordinator fail-closed）

### D10. 多调用/缺业务键 fail-closed

- 多调用 → 409
- `form_id` 或 `business_key` 为空 → 执行失败，状态 `failed`
- `write_action` 不在六种动作内 → 409
- 这些错误不产生写操作

### 5.3 网关实现

`governance/approval_gateway.py`：

```python
_WRITE_ACTIONS = frozenset({"save", "edit", "submit", "audit", "unaudit", "delete"})


class ApprovalGatewayImpl:
    def __init__(self, approvals: ApprovalService, tools: ToolRegistry) -> None: ...

    async def request(self, request: ApprovalRequest) -> str:
        if len(request.calls) != 1:
            raise ApprovalError("一次审批仅支持单个写操作", code="approval_conflict")
        call = request.calls[0]
        tool = self._tools.get(call.tool_name)
        if tool.action not in _WRITE_ACTIONS:
            raise ApprovalError("审批工具不是写操作", code="approval_conflict")

        digest = build_idempotency_key(request.user.user_id, call.tool_name, call.arguments)
        approval = await self._approvals.create(
            trace_id=request.trace_id,
            session_id=request.session_id,
            requester=request.user,
            tool_name=call.tool_name,
            arguments=call.arguments,
            summary=request.summary,
            form_id=tool.endpoint.form_id,
            business_key=_business_key(call.arguments),
            risk_score=request.risk.score,
            risk_level=request.risk.level,
            required_approvers=_merge_approvers(request.risk, request.permission),
            idempotency_key=f"{request.trace_id}:{digest}",
            write_action=tool.action,
        )
        return approval.approval_id
```

`_business_key` 依次取 `bill_no` / `business_key` / `order_no` / `document_number` / `number`；取不到返回空串（执行阶段 fail-closed）。

### 6.2 `ApprovalExecutor`

```python
class ApprovalExecutor:
    def __init__(
        self,
        approvals: ApprovalService,
        *,
        trace_store: TraceStore,
        writer: WriteCoordinator,
        executor: ToolExecutor,
        snapshots: SnapshotProvider,
        ledger: WriteLedger,
    ) -> None: ...

    async def execute(self, approval_id: str) -> PendingAction:
        async with self._lock_for(approval_id):
            action = await self._approvals.get_for_execution(approval_id)
            if action.status != "approved":
                raise ApprovalError("审批单未通过，不能执行", code="approval_conflict")
            if action.execution_status == "succeeded":
                return action

            if self._ledger_has_success(action):
                return await self._approvals.finish_execution(
                    approval_id,
                    succeeded=True,
                    result={"recovered_from_ledger": True},
                    error="",
                )

            action = await self._approvals.begin_execution(approval_id)
            try:
                trace = self._trace_store.load(action.trace_id)
            except TraceStoreError:
                return await self._approvals.finish_execution(
                    approval_id,
                    succeeded=False,
                    result={},
                    error="Trace 不存在，无法恢复执行",
                )
            if trace.user_id != action.requester_id:
                return await self._approvals.finish_execution(... "Trace 归属不符")

            try:
                result = await self._writer.execute(
                    trace,
                    [self._operation(action)],
                    self._executor,
                    self._snapshots,
                    saga_id=action.approval_id,
                )
            except Exception as exc:
                logger.exception("审批执行异常 | approval_id={}", approval_id)
                return await self._approvals.finish_execution(
                    approval_id,
                    succeeded=False,
                    result={},
                    error=f"执行异常: {type(exc).__name__}",
                )

            success = result.saga.status == SagaStatus.SUCCESS
            return await self._approvals.finish_execution(
                approval_id,
                succeeded=success,
                result={
                    "saga_id": result.saga.saga_id,
                    "status": result.saga.status.value,
                    "steps": len(result.saga.step_results),
                    "dead_letter": result.dead_letter is not None,
                },
                error="" if success else (result.saga.error or "Saga 失败"),
            )
```

`_operation` 构造 `WriteOperation`；`form_id`/`business_key` 为空时抛 `ValueError`，由外层捕获并标记 failed（零写入）。

### 6.3 账本恢复判断

```python
def _ledger_has_success(self, action: PendingAction) -> bool:
    for record in self._ledger.find_by_trace_id(action.trace_id):
        if (
            record.status == "success"
            and record.form_id == action.form_id
            and record.business_key == action.business_key
            and record.action == action.write_action
        ):
            return True
    return False
```

## 7. ApprovalService 扩展

新增方法（全部按单加锁）：

```python
async def get_for_execution(self, approval_id: str) -> PendingAction: ...
async def begin_execution(self, approval_id: str) -> PendingAction: ...
async def finish_execution(
    self,
    approval_id: str,
    *,
    succeeded: bool,
    result: Mapping[str, Any],
    error: str,
) -> PendingAction: ...
```

- `begin_execution`：
  - 要求 `status=approved`
  - `succeeded` → 直接返回
  - `not_started/failed/running` → `running`，审计 `approval.execution_started`
- `finish_execution`：
  - `succeeded` → `succeeded`，`executed_at=now`，审计 `approval.executed`
  - 失败 → `failed`，`execution_error=redact_text(error)[:500]`，审计 `approval.execution_failed`
  - 不修改 `status`（仍为 approved/rejected）

## 13. 风险与边界

| 风险 | 处理 |
|------|------|
| 本地幂等不覆盖金蝶写成功但账本未落 | 真实写接口透传 vendor 幂等键；文档明确 |
| 默认注册表无写工具 | 执行 fail-closed；T05 用 FakeExecutor 验证链路 |
| `edit/delete` 缺真实快照 | NoopSnapshotProvider 会让 WriteCoordinator 抛 SnapshotError → failed |
| 多调用审批 | 409 fail-closed，不拆分 |
| 审批通过但执行失败 | 审批保持 approved，execution_status=failed；手动 `/execute` 重试 |
| 进程崩溃在 running | 重启后手动 `/execute`，账本成功记录则跳过 |
| 多 worker | 进程内执行锁失效；单 worker，跨进程归 M9-T11 |
| 审批结果未回写会话 | 通过审批详情/审计查看；会话回写归 T06 |
| 审批接口阻塞等待写操作 | 本轮同步执行；后续可改后台任务/队列 |
