## 1. 任务回顾

### 1.1 目标

把「内部知识文档」变成「可检索的本地索引」，为 M9-T09 的检索问答提供地基：

- 支持 md / txt 目录导入
- 按标题 / 段落分块，保留来源元数据（文档、路径、标题、段落标题）
- 本地 BM25 + 中文字符 n-gram 索引，**不引入外部向量库/新依赖**
- 文档版本化 + 增量更新（新增 / 修改 / 删除只动变化部分）
- 入库前过分级与 DLP 门禁，敏感文档不落索引

### 1.2 本卡做

| 能力 | 说明 |
|------|------|
| 目录扫描 | `*.md` / `*.markdown` / `*.txt`，递归、跳过隐藏项与符号链接 |
| 分级门禁 | 按一级目录名判定等级，只允许 `public` / `internal` 入库 |
| DLP 门禁 | 全文扫描手机号/身份证/银行卡/邮箱，命中即整篇跳过 |
| 分块 | Markdown 标题切片 → 段落贪心打包 → 超长段落带重叠硬切 |
| 索引 | 本地 BM25（k1=1.5, b=0.75）+ 中文字符 unigram/bigram |
| 检索原语 | `RagIndex.search(query, top_k=5)`，固定语料 top5 可断言 |
| 持久化 | `{rag_index_dir}/index.json`，原子写 + 0600 + 写后自检 |
| 增量 | 内容 SHA-256 对比；重复导入幂等；删除/修改后索引一致 |
| 可重建 | 删除索引文件后重新摄入即可全量重建 |
| CLI | `scripts/rag_ingest.py` + `make rag-ingest`（薄封装，仅开发辅助） |

### 1.3 本卡明确不做

- **不做 `kb_search` 工具、意图分流、引用格式**：归 M9-T09
- **不做向量检索 / embedding / 重排序**：本卡只用 BM25，避免新依赖
- **不做 PDF / Word / HTML 解析**：只支持纯文本与 Markdown
- **不做中文分词词典**：用字符 unigram + bigram，零依赖且对中文召回稳定
- **不做 API / 控制台 UI**：T09 接入主循环后再考虑对外入口
- **不做跨进程写锁**：单 worker 假设，跨进程锁归 M9-T11
- **不做知识类评测集**：T09 并入 M8 评测与发布门禁
- **不做文档级权限过滤**：当前只有分级入库门禁，检索期权限归 M9-T11

### 1.4 验收标准（来自任务卡）

- [ ] 固定语料 top5 召回符合预期
- [ ] 重复导入幂等
- [ ] 删除 / 更新文档后索引一致

## 3. 关键设计决策（需审批）

### D1. 知识源与索引目录可配置

```python
rag_source_dir: Path = Path.home() / ".kingpilot" / "knowledge"
rag_index_dir: Path = Path.home() / ".kingpilot" / "rag_index"
```

- 运行时数据一律放用户目录，**不默认写仓库**
- 测试通过构造参数指向 `tmp_path`，不依赖 Settings
- CLI 支持 `--source` / `--index-dir` 覆盖

### D2. 只收 md / txt，且先做文件安全过滤

- 后缀白名单：`.md`、`.markdown`、`.txt`（大小写不敏感）
- 跳过：隐藏文件/目录（`.` 开头）、符号链接、非普通文件
- 单文件上限 1 MiB；超限跳过并计入报告
- 非 UTF-8 文件跳过并计入报告（不猜编码，避免乱码入库）
- 路径统一转相对路径 + `/` 分隔，**索引内不存绝对路径**（除 `source_root` 一项）

### D3. 分级用「一级目录名」声明，规则与逻辑分离

`config/rag_rules.py`：

```python
RAG_LEVEL_BY_DIR: dict[str, DataLevel] = {
    "public": "public",
    "internal": "internal",
    "sensitive": "sensitive",
    "high_sensitive": "high_sensitive",
}
RAG_INGEST_ALLOWED_LEVELS: frozenset[str] = frozenset({"public", "internal"})
```

- 例：`public/sales-order.md` → public；`sensitive/contacts.md` → sensitive
- 没有前缀目录的文档默认 `internal`
- 本卡只允许 public / internal 入库；sensitive / high_sensitive **整篇跳过**（reason=`level_denied`）
- 不做内容级自动分级（误判风险高），分级由目录约定负责

### D4. DLP 命中整篇拒绝，不脱敏后入库

- 对全文做 `DlpScanner.scan`
- 命中任意 PII → 跳过该文档，reason=`sensitive_content`
- 报告只记录「路径 + 原因」，**不记录命中类别以外的任何原值**
- 理由：脱敏会破坏知识语义，且敏感文档本就不该进入知识库

### D5. 分块：标题优先、段落次之、字符上限兜底

- 以 Markdown 标题（`#`～`######`）切 section；无标题的 txt 视为单 section
- section 内按空行切段落，贪心打包到 `RAG_CHUNK_MAX_CHARS=800`
- 单段落超过上限 → 按 `800 - 100` 步长硬切，保留 `100` 字符重叠，避免答案被切断
- 尾部碎片小于 `RAG_CHUNK_MIN_CHARS=60` 时优先并入上一块
- 整篇不足 60 字符仍保留一块（不丢文档）
- `chunk_id = f"{doc_id}-{序号:04d}"`，内容不变时 ID 稳定

### D6. 分词：中文字符 unigram + bigram，英文/数字按词

- 输入先 `NFKC` 归一 + 小写
- **文档侧**：中文连续串输出单字 + 相邻双字（如「销售订单」→ 销/售/订/单/销售/售订/订单）
- **查询侧**：中文多字串只用双字；只有单字查询才用单字
- 英文/数字：`[a-z0-9]+`
- 理由：零依赖、无需词典；bigram 解决中文短语匹配。查询侧不拆单字是为了
  避免「报销流程」被文档里的「销售」的「销」字误命中

### D7. BM25 参数固定并配置化

```python
RAG_BM25_K1 = 1.5
RAG_BM25_B = 0.75
```

- `idf = log(1 + (N - df + 0.5) / (df + 0.5))`
- 文档长度 = chunk 的 token 数（heading + content）
- 排序：分数降序，同分按 `chunk_id` 升序，保证可复现
- 空查询 / 零命中 → 返回空列表（T09 据此回复「知识库没有」）

### D8. 索引文件是唯一真相，加载时重建内存倒排

`{rag_index_dir}/index.json`：

```json
{
  "schema_version": 1,
  "built_at": "2026-10-19T12:00:00Z",
  "source_root": "/abs/path/to/knowledge",
  "documents": [
    {"doc_id": "…", "path": "public/a.md", "title": "…", "level": "public",
     "content_hash": "sha256…", "size_bytes": 123, "chunk_count": 3}
  ],
  "chunks": [
    {"chunk_id": "…-0000", "doc_id": "…", "path": "public/a.md", "title": "…",
     "heading": "创建销售订单", "chunk_index": 0, "content": "…", "char_count": 456}
  ]
}
```

- **不持久化倒排表**：加载时从 chunks 现算 token 统计，文件更小、结构更稳
- 原子写：`.tmp` → 自检（Pydantic + 引用完整性）→ `replace`
- 目录 0700、文件 0600
- schema 版本不符 / JSON 损坏 / chunk 引用不存在的 doc → `rag_index_invalid`（fail-closed）
- 索引不存在 → `RagIndex.empty()`（T09 可回答「知识库没有」）

### D9. 增量：按路径 + 内容哈希对比

| 情况 | 处理 |
|------|------|
| 路径与 hash 都相同 | 复用旧文档与旧 chunks（`unchanged`） |
| 路径相同、hash 不同 | 丢弃旧 chunks，重新分块（`updated`） |
| 新路径 | 新增（`added`） |
| 旧索引有、源目录没有 | 删除（`removed`） |
| `source_root` 与旧索引不一致 | 视为换库，全量重建（旧文档全部计 removed） |

- 重复导入且无变化 → `written=false`，不重写文件（严格幂等）
- 有变化才原子写；写后自检

### D10. 摄入结果必须结构化，不能只打日志

`RagIngestReport`：

```python
added / updated / removed / unchanged / chunks / written
skipped: list[{path, reason}]
```

`reason` 闭集：`level_denied` / `sensitive_content` / `too_large` /
`unsupported_encoding` / `unsupported_suffix` / `empty_document` /
`read_error` / `symlink`。

- 跳过不是异常：单篇文档失败不影响整库摄入
- 源目录不存在 / 不可读 → 抛 `RagError(rag_source_missing)`（fail-closed）

### D11. 本卡只做 CLI，不进 API

- `scripts/rag_ingest.py`：
  - 默认读 Settings 的两个目录
  - `--source` / `--index-dir` / `--json` / `--query` / `--top-k`
  - `--query` 摄入后直接检索，便于人工验收 top5
- `make rag-ingest` 作为开发辅助，**不进六门禁**
- 理由：T09 才需要对话入口；提前暴露 API 会扩大本卡范围

### D12. 摄入审计事件

`AuditEventType` 新增 `rag.indexed`：

- 只在真正写索引时发一条（`written=true`）
- detail 只放：`documents + added/updated/removed/unchanged + chunks + source_root`
- **不放任何文档内容、标题或分块文本**

## 6. 核心算法与关键代码

### 6.1 分词（`governance/rag/index.py`）

```python
_CJK_RUN = re.compile(r"[\u4e00-\u9fff]+")
_LATIN_RUN = re.compile(r"[a-z0-9]+")


def tokenize(text: str) -> list[str]:
    """文档侧分词：中文单字 + 相邻双字，英文/数字按词。"""
    normalized = unicodedata.normalize("NFKC", text).lower()
    tokens: list[str] = []
    for run in _CJK_RUN.findall(normalized):
        tokens.extend(run)                          # unigram：兜底单字查询
        tokens.extend(run[i : i + 2] for i in range(len(run) - 1))  # bigram：短语匹配
    tokens.extend(_LATIN_RUN.findall(normalized))
    return tokens


def tokenize_query(text: str) -> list[str]:
    """查询侧分词：多字中文只用 bigram，单字才用 unigram。"""
    normalized = unicodedata.normalize("NFKC", text).lower()
    tokens: list[str] = []
    for run in _CJK_RUN.findall(normalized):
        if len(run) == 1:
            tokens.append(run)
        else:
            tokens.extend(run[i : i + 2] for i in range(len(run) - 1))
    tokens.extend(_LATIN_RUN.findall(normalized))
    return tokens
```

### 6.2 BM25 检索（`governance/rag/index.py`）

```python
def search(self, query: str, *, top_k: int = RAG_DEFAULT_TOP_K) -> list[RagSearchHit]:
    """BM25 检索；空查询/零命中返回 []，由 T09 负责「知识库没有」话术。"""
    terms = sorted(set(tokenize_query(query)))      # 查询去重，避免重复词加权
    if not terms:
        return []
    limit = max(1, min(top_k, RAG_MAX_TOP_K))
    scores: dict[str, float] = {}
    for term in terms:
        postings = self._postings.get(term)
        if not postings:                            # 词不在库中：跳过
            continue
        df = len(postings)
        idf = math.log(1 + (self._chunk_count - df + 0.5) / (df + 0.5))
        for chunk_id, tf in postings.items():
            dl = self._lengths[chunk_id]
            denominator = tf + RAG_BM25_K1 * (
                1 - RAG_BM25_B + RAG_BM25_B * dl / self._avg_length
            )
            scores[chunk_id] = scores.get(chunk_id, 0.0) + (
                idf * tf * (RAG_BM25_K1 + 1) / denominator
            )
    ranked = sorted(scores.items(), key=lambda item: (-item[1], item[0]))[:limit]
    return [self._to_hit(chunk_id, round(score, 6)) for chunk_id, score in ranked]
```

### 6.3 分块（`governance/rag/chunking.py`）

```python
def chunk_document(text: str, *, doc_id: str, path: str, title: str) -> list[RagChunk]:
    """标题切片 → 段落打包 → 超长硬切；chunk_id 内容不变则稳定。"""
    chunks: list[RagChunk] = []
    index = 0
    for heading, body in _split_sections(text, default_heading=title):
        for content in _pack_paragraphs(body):
            chunks.append(
                RagChunk(
                    chunk_id=f"{doc_id}-{index:04d}",
                    doc_id=doc_id,
                    path=path,
                    title=title,
                    heading=heading,
                    chunk_index=index,
                    content=content,
                    char_count=len(content),
                )
            )
            index += 1
    return chunks
```

`_split_sections` 用 `^(#{1,6})\s+(.+)$` 识别标题；`_pack_paragraphs` 按空行切段，
贪心累加到 `RAG_CHUNK_MAX_CHARS`，超长段落按 `MAX - OVERLAP` 步长硬切。

### 6.4 增量摄入（`governance/rag/ingest.py`）

```python
class RagIngestor:
    def __init__(
        self,
        *,
        source_root: Path,
        index_dir: Path,
        scanner: DlpScanner | None = None,
        audit: AuditLogger | None = None,
        clock: Callable[[], datetime] | None = None,
    ) -> None: ...

    def refresh(self) -> RagIngestReport:
        """扫描源目录，按内容哈希增量重建索引，返回结构化报告。"""
```

流程：

```text
refresh()
  → source_root 必须是目录，否则 RagError(rag_source_missing)
  → 读取旧 index（不存在 = empty；损坏 = RagError，不静默重建）
  → 遍历 source_root.rglob("*")（排序，保证确定性）
      → 隐藏项/符号链接/目录 → 跳过
      → 后缀不在白名单 → skipped(unsupported_suffix)
      → 级别不在允许集合 → skipped(level_denied)
      → 超过 1 MiB → skipped(too_large)
      → UTF-8 解码失败 → skipped(unsupported_encoding)
      → DLP 命中 → skipped(sensitive_content)
      → hash 与旧文档一致 → 复用旧 chunks（unchanged）
      → 否则重新分块（added / updated）
  → 旧索引中未再出现的路径 → removed
  → 无变化且索引已存在 → written=false，直接返回
  → 原子写 index.json → 加载自检 → 审计 rag.indexed
```

## 11. 风险与边界

| 风险 | 处理 |
|------|------|
| 中文分词质量 | bigram 提升短语匹配；效果不足时 T09 再加轻量重排 |
| 大文档内存占用 | 单文件 1 MiB 上限；chunk 上限 800 字符 |
| 索引文件膨胀 | 不存倒排表，加载时现算；BM25 只存文本与元数据 |
| 并发写索引 | 单 worker + 原子写；跨进程锁归 T11 |
| 分级靠目录约定 | 明确写入文档；内容级自动分级误判风险更高 |
| DLP 只覆盖四类 PII | 与全项目口径一致；后续可扩展正则 |
| 删除源文件后索引残留 | 每轮全目录扫描，按路径差集删除 |
| 索引损坏 | fail-closed，报 `rag_index_invalid`；用户删除后重建 |
| Markdown 表格/代码块 | 按普通段落处理，不破坏内容；结构化解析留待后续 |

## 12. 学习指引

1. **为什么 RAG 第一步不是接向量库**：先解决「文档怎么切、怎么增量、怎么可追溯」，向量库只是召回算法的一种替换。
2. **为什么用字符 bigram**：中文没有空格，零依赖分词最稳；bigram 能匹配「销售订单」这类短语。
3. **BM25 为什么还需要文档长度归一化**：长文档天然命中更多词，`b` 参数抑制长度偏置。
4. **为什么分级用目录而不是自动识别**：自动分级误判代价高；目录约定可审计、可评审。
5. **为什么 DLP 命中要整篇拒绝**：知识库会被长期保存和多人检索，脱敏会改变语义且仍有泄露风险。
6. **为什么索引不存倒排表**：倒排表体积大且格式演进成本高；文本 chunk 才是唯一真相。
7. **为什么重复导入不重写文件**：幂等不仅是「结果相同」，还包括「没有副作用」。
8. **为什么 chunk_id 要稳定**：T09 的引用要能回溯；内容不变时 ID 变化会让引用失效。
