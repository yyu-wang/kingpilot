## 1. 任务回顾

### 1.1 目标

把单租户系统升级为「默认拒绝 + 路径隔离 + 资源隔离」的多租户形态：

- API Key 身份必须携带 `tenant_id`，缺失/非法启动期拒绝
- 会话 / Trace / 审计 / 账本 / 在线样本五类存储按租户命名空间隔离
- 审批、Badcase、看板、Provider（Prompt 灰度）、预算按租户隔离
- 跨租户读取统一 404/403，不暴露存在性
- 缺失租户上下文时拒绝执行

### 1.2 本卡做

| 能力 | 说明 |
|------|------|
| `TenantContext` | 租户 ID 模型 + contextvar + `tenant_scope` |
| API 认证 | `ApiKeyIdentity.tenant_id` 必填，缺失启动失败 |
| 五处存储 | session / trace / audit / ledger / sample 按租户路径 |
| 扩展隔离 | approval / badcase / dashboard / Provider 也按租户 |
| 预算隔离 | 每租户独立 `CostEngine` + `BudgetPolicy` |
| Prompt 灰度 | 租户 ID 作为 `rollout_key` |
| 默认拒绝 | 空/非法租户 ID、未知租户配置一律拒绝 |
| 越权测试 | 两租户会话/Trace/审批/Badcase/看板互不可见 |

### 1.3 本卡明确不做

- **不做租户管理 API**：租户清单在 `config/tenants.py`，新增租户改配置
- **不做数据库行级多租户**：当前存储是本地文件/SQLite，按目录/文件隔离
- **不做跨租户管理员视图**：看板只看本租户；平台级汇总后续再做
- **不做旧数据迁移工具**：`default` 租户继续使用原路径，命名租户走 `tenants/{id}/`
- **不做租户级 Prompt 精确版本锁定**：用 `rollout_key=tenant_id` 做确定性灰度
- **不做跨进程锁**：单 worker 假设不变

### 1.4 验收标准（来自任务卡）

- [ ] 两个租户数据/会话/预算互不可见
- [ ] 缺少租户上下文拒绝
- [ ] 跨租户读取返回 404/403
- [ ] 隔离测试覆盖五类存储

## 3. 关键设计决策（需审批）

### D1. `default` 租户沿用原路径，命名租户走 `tenants/{id}/`

```python
DEFAULT_TENANT = "default"

def tenant_dir(base: Path, tenant_id: str) -> Path:
    return base if tenant_id == DEFAULT_TENANT else base / "tenants" / tenant_id

def tenant_file(base_file: Path, tenant_id: str) -> Path:
    return (
        base_file
        if tenant_id == DEFAULT_TENANT
        else base_file.parent / "tenants" / tenant_id / base_file.name
    )
```

- 好处：现有 CLI/API 测试与本地数据零迁移，单租户行为不变
- 命名租户 `alpha` 的路径形如：
  - `sessions/tenants/alpha/users/{user_id}/`
  - `traces/tenants/alpha/`
  - `tenants/alpha/audit.jsonl`
  - `tenants/alpha/ledger.sqlite3`
  - `samples/tenants/alpha/`
- `default` 与 `alpha` 仍然完全隔离（不同目录/文件）

### D2. 租户身份来自 API Key，缺失启动期拒绝

- `ApiKeyIdentity.tenant_id`：**必填**，格式 `^[a-z0-9][a-z0-9._-]{0,31}$`
- 配置缺 `tenant_id` → `ApiKeyConfigError`（fail-closed，启动失败）
- `UserContext.tenant_id`：默认 `default`（兼容 CLI/单测）
- 非 API 入口（CLI）固定 `default`

### D3. `TenantContext` + contextvar 贯穿审计与运行

```python
@dataclass(frozen=True)
class TenantContext:
    tenant_id: str
```

- `tenant_scope(tenant_id)`：contextvar 设置/恢复，非法 ID 抛 `TenantError`
- `AgentCore.run` 在入口进入 `tenant_scope`，保证 LLM/工具/审计/成本都在租户上下文内
- API 的 `get_current_user` 用 yield 依赖设置 scope，覆盖审批/Badcase 等路由级审计

### D4. `AppDeps` 按租户懒加载 `TenantResources`

```python
@dataclass(frozen=True)
class TenantResources:
    tenant: TenantContext
    provider: LLMProvider
    cost_engine: CostEngine
    rollout_key: str
    safety: SafetyLayer
    trace_store: TraceStore
    ledger: WriteLedger
    writer: WriteCoordinator
    approvals: ApprovalService
    approval_execution: ApprovalExecution
    dashboard: DashboardService
    badcases: BadcaseService
    sampler: OnlineSampler | None
```

- `resources_for(tenant_id)` 首次构建并缓存；同一租户共享服务实例
- 保留 `deps.trace_store / approvals / dashboard / badcases / sampler` 属性指向
  `default` 租户，兼容既有测试与脚本
- 每租户 Provider 使用 `rollout_key=tenant_id`，预算用该租户 `BudgetPolicy`

### D5. 五类存储隔离方式

| 存储 | 隔离方式 |
|------|----------|
| Session | `session_root/users/{user_id}`，`session_root` 按租户 |
| Trace | 每租户独立 `TraceStore(trace_dir)` |
| Audit | `JsonlAuditSink(tenant_aware=True)`，按 `event.tenant_id` 路由 |
| Ledger | 每租户独立 `SqliteWriteLedgerStore(ledger_path)` |
| Sample | 每租户独立 `OnlineSampler(sample_dir)` |

扩展：
- Approval / Badcase / Dashboard 均由 `TenantResources` 按租户构建
- `AuditEvent.tenant_id` 新增字段；`AuditLogger.emit` 未填时从 contextvar 补齐

### D6. 预算隔离：每租户独立 CostEngine + BudgetPolicy

- `TenantResources.cost_engine = CostEngine(sink=...)`
- `RoutingProvider` 的预算来自 `TenantProfile.llm_budget_usd`（缺省用全局 Settings）
- 租户 A 预算耗尽不影响租户 B
- 设计上不做「全局共享 CostEngine + 按租户过滤」，避免一个租户的调用污染另一个租户的降档状态

### D7. Prompt 灰度按租户确定性选择

- `TenantProfile.prompt_rollout_key` 缺省 = `tenant_id`
- 构建 Provider 时传 `rollout_key`
- 同一租户永远命中同一灰度版本；回滚仍走 M8 的 `rollout.json`

### D8. 默认拒绝

- API Key 缺租户 → 启动失败
- 空/非法租户 ID → `TenantError`
- 跨租户读取 → 404（不区分「不存在」与「无权限」）
- 未知租户 ID：允许路径级隔离，但 API Key 配置即租户白名单；配置里没有的租户无法认证

### D9. 租户配置集中声明

`config/tenants.py`：

```python
@dataclass(frozen=True)
class TenantProfile:
    tenant_id: str
    llm_budget_usd: float | None = None
    prompt_rollout_key: str | None = None

TENANT_PROFILES = {"default": TenantProfile("default")}

def tenant_profile(tenant_id: str) -> TenantProfile:
    return TENANT_PROFILES.get(tenant_id, TenantProfile(tenant_id))
```

- 新增租户只改配置（并可同步一条 API Key 身份）
- 未声明租户使用默认预算与 `tenant_id` 作为灰度 key

### D10. 不改变业务语义

- 只读/写/审批/评测逻辑不变
- 只改变「资源实例与路径」以及「身份必须带租户」
- 既有单租户测试通过 `default` 路径保持兼容

**实现补充（2026-10-19）**：

- `default` 租户保留旧路径；命名租户统一 `tenants/{id}/`，旧数据零迁移
- API Key 身份缺 `tenant_id` 在启动期抛 `ApiKeyConfigError`
- API `get_current_user` 用 yield 依赖设置租户上下文，覆盖路由级审计
- `AgentCore.run` 入口再次进入 `tenant_scope`，覆盖 LLM/工具/成本旁路
- 每租户资源由 `AppDeps.resources_for` 懒加载并缓存；默认租户属性兼容旧测试

## 5. 路径与上下文实现

### 5.1 `infrastructure/tenancy.py`

```python
@dataclass(frozen=True, slots=True)
class TenantPaths:
    session_root: Path
    trace_dir: Path
    audit_path: Path
    ledger_path: Path
    sample_dir: Path
    approval_dir: Path
    badcase_dir: Path


def tenant_paths(settings: Settings, tenant_id: str) -> TenantPaths:
    tenant = validate_tenant_id(tenant_id)
    return TenantPaths(
        session_root=tenant_dir(settings.session_store_dir, tenant),
        trace_dir=tenant_dir(settings.trace_store_dir, tenant),
        audit_path=tenant_file(settings.audit_log_path, tenant),
        ledger_path=tenant_file(settings.ledger_db_path, tenant),
        sample_dir=tenant_dir(settings.online_sample_dir, tenant),
        approval_dir=tenant_dir(settings.approval_store_dir, tenant),
        badcase_dir=tenant_dir(settings.badcase_store_dir, tenant),
    )
```

Contextvar：

```python
_current_tenant: ContextVar[str] = ContextVar("kingpilot_tenant", default=DEFAULT_TENANT)

@contextmanager
def tenant_scope(tenant_id: str) -> Iterator[str]:
    validated = validate_tenant_id(tenant_id)
    token = _current_tenant.set(validated)
    try:
        yield validated
    finally:
        _current_tenant.reset(token)
```

### 5.2 审计路由

```python
class JsonlAuditSink:
    def __init__(self, path: Path, *, tenant_aware: bool = False) -> None: ...

    def write(self, event: AuditEvent) -> None:
        path = (
            tenant_file(self._path, event.tenant_id or DEFAULT_TENANT)
            if self._tenant_aware
            else self._path
        )
        ...
```

`AuditLogger.emit`：

```python
if not event.tenant_id:
    event = event.model_copy(update={"tenant_id": current_tenant()})
```

@dataclass
class AppDeps:
    settings: Settings
    client: KingdeeClient

    def resources_for(self, tenant_id: str) -> TenantResources: ...

    def build_core(self, memory, *, user: UserContext, event_sink=None) -> AgentCore: ...

### 6.2 `get_current_user`

```python
async def get_current_user(...) -> AsyncIterator[UserContext]:
    identity = ...
    user = UserContext(tenant_id=identity.tenant_id, ...)
    with tenant_scope(user.tenant_id):
        yield user
```

## 11. 风险与边界

| 风险 | 处理 |
|------|------|
| 默认租户走旧路径 | 明确设计；命名租户全隔离 |
| 进程内缓存资源 | 单 worker 假设；跨进程锁不在本卡 |
| Provider 每租户一个连接池 | 租户数受 API Key 白名单控制；`aclose` 统一释放 |
| Prompt 灰度只按租户 | 不做用户/会话级组合键，避免不可复现 |
| 旧数据不迁移 | default 保持原路径；迁移工具后续 |
| 审计事件漏填租户 | call-time contextvar 兜底 + sink 路由 |
| 审批执行跨租户 | 每租户独立 ApprovalService/Executor |

## 12. 学习指引

1. **为什么租户上下文用 contextvar**：审计、成本等旁路代码不该层层传参。
2. **为什么 default 保留旧路径**：迁移成本高且单租户行为不应变化。
3. **为什么每租户独立 CostEngine**：共享账本会让 A 的消费触发 B 的降档。
4. **为什么跨租户统一 404**：403 会暴露「该资源存在」。
5. **为什么 API Key 必须带租户**：身份是租户边界的唯一可信来源。
6. **为什么 Prompt 灰度用租户 key**：同一租户必须稳定命中同一版本。
7. **为什么审批/Badcase 也要隔离**：它们包含业务动作与问题原文，泄露面比会话更大。
8. **为什么先做文件级隔离**：当前存储就是文件/SQLite，目录隔离最小且可审计。
