## 1. 任务回顾

### 1.1 目标

把 M9-T08 的「本地索引 + BM25 检索」接进 Agent 主循环，让知识类问题走知识库而不是 ERP 查询：

- 新增只读工具 `kb_search`，由 LLM 按工具描述自主选择
- top12 召回 → 轻量重排 → top5 注入上下文
- 回答强制引用原文段落：`《文档标题》第 N 段（段落标题）`
- 无命中时明确回复「知识库没有找到相关文档。」，禁止编造
- 知识问题不误触发 ERP 查询工具
- 补充知识类评测题，纳入 M8 发布门禁

### 1.2 本卡做

| 能力 | 说明 |
|------|------|
| `kb_search` 工具 | 本地只读工具，参数 `query` + `limit`，Schema 由 Pydantic 生成 |
| 本地工具框架 | `ToolDefinition` 支持 `runner`，与金蝶端点工具共存 |
| 检索服务 | `KnowledgeRetriever`：索引热加载 + BM25 top12 + 重排 + 单文档最多 2 条 |
| 引用策略 | 生成后校验引用；缺失/伪造引用 → 确定性摘录兜底 |
| 无命中兜底 | 固定文案，覆盖 LLM 任意编造 |
| Prompt v2 | 新增知识库回答规则，active 切到 v2 |
| 安全适配 | 本地工具走工具层权限；跳过 FilterString/实体预检/行级过滤 |
| 规则引擎防误判 | 知识意图（怎么/流程/规范/步骤）不降级成 ERP 查询 |
| 评测 | 评测集新增 8 道知识题（expected=`kb_search`），沿用发布门禁 |
| 追踪 | Trace 记录 citations / no_hit / fallback |

### 1.3 本卡明确不做

- **不做向量检索 / embedding / 重排模型**：仍用 BM25 + 规则重排
- **不做 LLM 二次纠错**：引用不合规直接走确定性摘录兜底，不重复调用 LLM
- **不做知识类 LLM 主观评分**：评测沿用 M8 工具选对率口径
- **不做文档级权限**：知识库对所有已认证角色可见，权限隔离归 M9-T11
- **不做 API/控制台新入口**：`kb_search` 随现有 `/v1/chat` 自动生效
- **不做多轮知识追问的额外检索策略**：多轮指代仍由现有记忆层负责

### 1.4 验收标准（来自任务卡）

- [ ] 引用可回溯到原文段落
- [ ] 无命中不编造
- [ ] 知识问题不误触发 ERP 工具
- [ ] 评测集通过率达标并纳入发布门禁

## 3. 关键设计决策（需审批）

### D1. 扩展 `ToolDefinition` 支持本地执行器，不复制一套注册表

```python
LocalRunner = Callable[[KingPilotBaseModel], Awaitable[Any]]

@dataclass(frozen=True)
class ToolDefinition:
    spec: ToolSpec
    params_model: type[KingPilotBaseModel]
    build_filter: Callable[[KingPilotBaseModel], str] | None = None
    endpoint: EndpointDescriptor | None = None
    runner: LocalRunner | None = None
    tool_type: ToolType = "query"
    ...

    @property
    def is_local(self) -> bool:
        return self.runner is not None
```

- 金蝶查询工具行为不变（runner=None，走 endpoint + build_filter）
- 本地工具走 `runner`，不碰 `KingdeeClient`
- 仍共用：Schema 生成、工具白名单、语义缓存、事件、Trace、记忆

### D2. `kb_search` 只读、参数收敛

```python
class KnowledgeParams(KingPilotBaseModel):
    query: str = Field(min_length=1, max_length=200, description="知识问题或关键词")
    limit: int = Field(default=5, ge=1, le=10, description="返回片段数")
```

- 字段名用 `limit` 而非 `top_k`：复用 Guard 4 的分页硬上限检查
- 不暴露文档路径、等级、索引参数给 LLM
- 工具描述明确：「仅用于操作手册/流程/规范类问题，不查 ERP 实时单据」

### D3. 检索：BM25 top12 → 轻量重排 → top5

重排规则（确定性、零 LLM）：

| 信号 | 加分 |
|------|------|
| 查询原文出现在段落标题 | +0.50 |
| 查询词与标题词重合率 × 0.3 | 0 ~ +0.30 |
| 文档标题出现在查询中 | +0.20 |

- 排序：重排分降序，同分按 `chunk_id` 升序
- 同一文档最多保留 2 条，避免一份手册刷屏
- 最终取 5 条（`RAG_ANSWER_TOP_K=5`）

### D4. 索引热加载 + 失败降级为「无命中」

- 首次检索懒加载 `index.json`
- 按 `(mtime_ns, size)` 判断索引是否变化，变化则重载（`make rag-ingest` 后无需重启）
- 索引不存在 → 空索引（no_hit）
- 索引损坏 → 记 WARNING，本次按空索引处理（**不打断对话**）
- 理由：T08 摄入侧已 fail-closed；问答侧优先保证可用性，且无命中话术是安全兜底

### D5. 引用格式与强制校验

格式：

```text
《销售订单操作手册》第 2 段（审核销售订单）
```

- `N = chunk_index + 1`（文档内序号，可回溯到具体分块）
- `CitationPolicy.enforce(answer, result)`：
  1. `no_hit` → 固定回复 `知识库没有找到相关文档。`
  2. 回答中至少出现一个 **本次命中分块** 的合法引用 → 保留回答，并追加确定性「参考来源」
  3. 引用缺失或引用了不存在的文档 → 用 top1 命中做确定性摘录兜底：
     ```text
     根据《文档》第 N 段（段落标题）：<原文>

     参考来源：
     - 《文档》第 N 段（段落标题）
     ```
- 兜底不调用 LLM，保证「引用可回溯」与「不编造」是硬约束

**实现补充（2026-10-19）**：

- `Trace.citations` 记录本次注入的全部分块引用（即「参考来源」列表），不只记录正文出现的那一条
- 引用段号是序数，幻觉检测器已补充「第 N / 第 N 段」含空格时的序数豁免，
  避免 `《文档》第 2 段` 被误判为「数字 2 不在工具结果中」

### D6. 知识问题不误触发 ERP 工具

- 工具描述层面：`kb_search` 明确「知识/流程/手册」；ERP 工具描述保持「实时单据数据」
- Prompt 层面：知识库规则要求不得把知识内容说成实时 ERP 数据
- 规则引擎层面：命中「怎么/如何/流程/规范/手册/制度/步骤/说明」且没有
  SO/CUS/SUP/MAT 显式编码时，不降级为 ERP 查询
- 评测层面：新增 8 道知识题，expected_tool=`kb_search`

### D7. 无命中固定文案由代码强制，不相信 LLM 自觉

- 常量：`KNOWLEDGE_NO_HIT_MESSAGE = "知识库没有找到相关文档。"`
- 只要本次调用了 `kb_search` 且 `no_hit=true`，最终答复必为该文案
- Trace 置 `citation_no_hit=true`，便于看板统计

### D8. 本地工具的权限与 Guard 旁路规则

| 环节 | 本地只读工具 |
|------|--------------|
| 工具层权限 | 仍受 `deny_tools / allow_tools` 约束 |
| 未知角色 | 拒绝（与现有角色矩阵一致） |
| 数据域 / 行级 / 列级 | 跳过（知识库不属于任何 ERP 数据域） |
| Guard 1 Schema | 正常校验 |
| Guard 2 FilterString | 跳过（无 FilterString） |
| Guard 3 实体预检 | 跳过（非写工具） |
| Guard 4 分页/无条件查询 | 校验 `limit` 范围，跳过「必须有过滤条件」 |
| Guard 5 写参数 | 跳过（非写工具） |
| 风险评分 | 作为 query 工具，风险低 → auto |
| 语义缓存 | 可缓存（只读） |

### D9. 引用校验放在 Phase 4 生成之后、Phase 5 幻觉检测之前

```text
Phase 4 generate
  → Phase 4.5 citation enforce（本卡新增）
  → Phase 5 hallucination detect
  → Phase 6 memory write
```

- 保证写入记忆与落盘 Trace 的答复已经是「带引用/无命中」版本
- LLM 降级收尾（`_finish_fallback`）同样执行引用校验
- Trace 新增字段：`citations / citation_enforced / citation_no_hit / citation_fallback`

### D10. Prompt 走版本管理，不改旧版本

- 新增 `prompts/generate/v2.txt`
- `prompts/rollout.json` 的 `generate.active` 切到 `v2`
- v1 保留可回滚

### D11. 知识评测复用 M8 评测集与门禁

- 在 `evals/datasets/v1/tool_selection.json` 追加 8 道知识题
- 期望工具 = `kb_search`（含一道预期无命中的问法）
- 数据集从 31 → 39 题；发布门禁仍用 `tool_selection_accuracy`（floor 0.90）
- 理由：本卡验收的是「知识问题是否选对工具」；召回/引用质量由确定性单测覆盖，

## 6. 核心实现

### 6.1 `agent/knowledge.py`

```python
KB_SEARCH_TOOL = "kb_search"


class KnowledgeParams(KingPilotBaseModel):
    query: str = Field(min_length=1, max_length=200)
    limit: int = Field(default=RAG_ANSWER_TOP_K, ge=1, le=10)


class KnowledgeService:
    """kb_search 的执行器：参数校验 → 检索 → 结构化结果。"""

    def __init__(self, *, index_dir: Path) -> None:
        self._retriever = KnowledgeRetriever(index_dir)

    async def run(self, params: KingPilotBaseModel) -> KnowledgeSearchResult:
        if not isinstance(params, KnowledgeParams):
            raise ToolError("kb_search 参数模型不匹配")
        return self._retriever.search(params.query, top_k=params.limit)
```

工具注册在 `build_default_registry()` 末尾：

```python
service = knowledge or KnowledgeService(index_dir=get_settings().rag_index_dir)
registry.register(
    ToolDefinition(
        spec=ToolSpec(
            name=KB_SEARCH_TOOL,
            description=(
                "查询内部知识库（操作手册/流程/规范/制度）。"
                "仅用于“怎么做、流程是什么、有什么规定”类知识问题；"
                "不查询订单、库存、客户等实时 ERP 数据。"
            ),
            parameters=KnowledgeParams.model_json_schema(),
        ),
        params_model=KnowledgeParams,

```

### 6.2 `governance/rag/retriever.py`

```python
class KnowledgeRetriever:
    def __init__(self, index_dir: Path, *, candidate_k=RAG_RETRIEVAL_TOP_K,
                 answer_k=RAG_ANSWER_TOP_K, max_per_doc=RAG_MAX_CHUNKS_PER_DOC) -> None: ...

    def search(self, query: str, *, top_k: int | None = None) -> KnowledgeSearchResult:
        candidates = self._index().search(query, top_k=self._candidate_k)
        hits = self._rerank(query, candidates, top_k or self._answer_k)
        return KnowledgeSearchResult(
            query=query,
            hits=hits,
            hit_count=len(hits),
            no_hit=not hits,
            message="" if hits else KNOWLEDGE_NO_HIT_MESSAGE,
        )
```

索引缓存：

```python
def _index(self) -> RagIndex:
    try:
        stat = self._index_path.stat()
    except FileNotFoundError:
        return RagIndex.empty()
    fingerprint = (stat.st_mtime_ns, stat.st_size)
    if fingerprint == self._fingerprint and self._cached is not None:
        return self._cached
    try:
        self._cached = RagIndex.load(self._index_path)
    except RagError as exc:
        logger.warning("RAG 索引不可用，按空索引处理: {}", exc)
        self._cached = RagIndex.empty()
    self._fingerprint = fingerprint
    return self._cached
```

### 6.3 `governance/rag/answer.py`

```python
def format_citation(hit: RagSearchHit) -> str:
    return f"《{hit.title}》第 {hit.chunk_index + 1} 段"


def enforce_citations(answer: str, result: KnowledgeSearchResult) -> CitationResult:
    if result.no_hit or not result.hits:
        return CitationResult(content=KNOWLEDGE_NO_HIT_MESSAGE, no_hit=True)

    citations = _unique([format_citation(hit) for hit in result.hits])
    if not any(citation in answer for citation in citations):
        # 引用缺失/伪造：用 top1 原文做确定性摘录，保证可回溯
        top = result.hits[0]
        content = f"根据{format_citation(top)}（{top.heading}）：{top.content}"
        content = f"{content}\n\n{_render_references(result.hits)}"
        return CitationResult(content=content, citations=citations, fallback_used=True)

    content = answer.strip()
    if "参考来源" not in content:
        content = f"{content}\n\n{_render_references(result.hits)}"
    return CitationResult(content=content, citations=citations)
```

## 11. 风险与边界

| 风险 | 处理 |
|------|------|
| LLM 不按引用格式回答 | 生成后强制校验，不合规走确定性摘录 |
| 知识问题被误判为 ERP | 工具描述 + Prompt + 规则引擎 + 评测题 |
| 索引更新后进程仍读旧索引 | 按 mtime/size 热加载 |
| 索引损坏导致对话崩溃 | 问答侧降级为空索引（T08 摄入侧仍 fail-closed） |
| 摘录兜底答案较长 | 只取 top1 原文 + 参考列表，不拼接多段 |
| 引用段号与用户直觉不一致 | 段号 = 文档内 chunk 序号，附标题便于定位 |
| 本地工具绕过数据域 | 只读知识库不属于 ERP 数据域；工具层 allow/deny 仍生效 |
| 知识库含敏感内容 | T08 入库 DLP 门禁；出站仍有全局 DLP |

## 12. 学习指引

1. **为什么知识工具要单独建模**：工具描述是 LLM 路由的第一信号，混进 ERP 工具会误触发。
2. **为什么重排不用模型**：规则重排可解释、可复现，先把召回质量做稳，再考虑模型重排。
3. **为什么要单文档上限**：BM25 容易让同一份长手册占满 top5，多样性影响答案覆盖。
4. **为什么引用要代码强制**：Prompt 是软约束，合规与可回溯必须由代码兜底。
5. **为什么无命中要固定文案**：LLM 在空结果上最容易编造，固定文案是最后一道防线。
6. **为什么本地工具跳过 FilterString Guard**：没有 FilterString 就没有注入面，强行套用会误杀。
7. **为什么索引热加载**：摄入是运维动作，不应要求重启对话服务。
8. **为什么评测复用工具选对率**：先保证「该不该查知识库」正确，再谈答案质量，指标可复现。
