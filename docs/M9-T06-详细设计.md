## 1. 任务回顾

### 1.1 目标

把散落在 Trace、Audit、Ledger 中的运行数据聚合成按天指标，提供只读运营看板 API：

- 幻觉率
- 拦截统计（Guard / 权限 / DLP）
- 成本趋势
- 风险分布
- 降级率
- 请求量、平均延迟、写操作成功/失败

### 1.2 本卡做

| 能力 | 说明 |
|------|------|
| 聚合服务 | `DashboardService`：按天聚合 + 总计 |
| API | `GET /v1/dashboard/overview` |
| 数据源 | Trace + Audit + Ledger + 成本事件 |
| 时间范围 | 默认近 7 天，最长 90 天，按配置时区切日 |
| 权限 | 仅 `admin` |
| 成本持久化 | 新增 `cost.recorded` 审计事件，CostEngine 落审计流 |
| 测试 | 指标口径、时区边界、空数据、权限、范围校验 |

### 1.3 本卡明确不做

- **不做看板 UI**：只提供 API；控制台后续再接
- **不做用户维度筛选**：本卡是全局运营视角，admin-only
- **不做实时推送/WebSocket**：按需查询
- **不做数据归档/清理**：本地文件与 SQLite 量级可接受
- **不返回明细**：只返回聚合数字，不下钻用户/请求原文
- **不新增成本数据库**：复用 Audit JSONL 作为成本事件流

### 1.4 验收标准（来自任务卡）

- [ ] 指标口径与 M8 离线评测一致（延迟/成本口径可对照）
- [ ] 按天聚合正确，跨天/时区边界正确
- [ ] 默认只出聚合，无原始敏感字段
- [ ] 查询延迟在本地文件量级可接受

## 2. 数据源盘点

| 指标 | 来源 | 字段 |
|------|------|------|
| 请求量 | Trace | 每条 trace 一条请求 |
| 幻觉率 | Trace | `hallucination_detected` |
| 降级率 | Trace | `used_fallback` |
| 风险分布 | Trace | `risk_assessment.level` |
| 平均延迟 | Trace | `total_latency_ms` |
| 拦截统计 | Audit | `guard.blocked` / `permission.denied` / `dlp.blocked` |
| 成本/Token/LLM 调用数 | Audit（新增） | `cost.recorded.detail` |
| 写操作成功/失败 | Ledger | `WriteRecord.status` |

### 2.1 成本数据的缺口

当前 `CostEngine` 只在进程内保存 `CostRecord`，Trace 的 `llm_token_usage` 未接线，重启即丢。

T06 补一个**最小持久化口**：

- `CostEngine(sink=...)` 已支持回调
- App 装配时注入 sink：把 `CostRecord` 写成 `AuditEvent(event_type="cost.recorded")`
- 看板从 Audit 流读取成本，不新增独立存储

这样成本趋势与拦截、审批共用同一 append-only 审计流，口径与留存一致。

## 3. 关键设计决策（需审批）

### D1. 仅 `admin` 可查看看板

- `role != "admin"` → 403 `forbidden`
- 理由：看板包含全局成本、风险分布、拦截统计；manager 只应看审批，不应看全局运营数据
- 后续如需部门维度，再加 scope

### D2. 单个 overview 接口返回「总计 + 每日序列」

```
GET /v1/dashboard/overview?from=2026-10-13&to=2026-10-19
```

- 一次读取、一次聚合，避免前端多次请求导致口径漂移
- 每日序列零填充：没有数据的日期也返回 0，便于画折线

### D3. 按配置时区切日，默认近 7 天，最长 90 天

- Settings 新增 `dashboard_timezone`，默认 `Asia/Shanghai`
- 所有存储时间都是 UTC；聚合时转本地时区再取 `date()`
- 默认 `to=今天（本地）`，`from=to-6天`
- `from > to` 或跨度 > 90 天 → 422 `invalid_range`
- 理由：运营看“今天/本周”按业务时区，不能用 UTC 切日

### D4. 指标口径固定

| 指标 | 公式 |
|------|------|
| `requests` | 该日 trace 数 |
| `hallucination_rate` | `hallucination_detected=true` 的 trace / requests |
| `fallback_rate` | `used_fallback=true` 的 trace / requests |
| `blocked.guard` | 该日 `guard.blocked` 审计事件数 |
| `blocked.permission` | 该日 `permission.denied` 审计事件数 |
| `blocked.dlp` | 该日 `dlp.blocked` 审计事件数 |
| `blocked.total` | 三类之和 |
| `risk_distribution` | trace.risk_assessment.level 计数，缺失归 `unknown` |
| `cost_usd` | `cost.recorded.detail.cost_usd` 求和 |
| `tokens` | prompt + completion token 求和 |
| `llm_calls` | `cost.recorded` 事件数 |
| `write_success` / `write_failed` | Ledger 记录按 status 计数 |
| `avg_latency_ms` | trace.total_latency_ms 平均（无请求 = 0） |

- 比率保留 4 位小数，成本保留 6 位，延迟保留 3 位
- 与 M8 对照：`avg_latency_ms`、`cost_usd` 的统计精度与 M8 报告一致；生产看板统计全部请求，M8 统计评测题，分母不同但单位一致

### D5. 只输出聚合，不输出明细

- API 不返回 user_id、trace_id、session_id、工具参数、用户输入
- 风险分布只有计数
- 拦截只有类别计数
- 满足「看板可下钻到 trace」时再单独做鉴权接口，不在本卡

### D6. 扩展 `TraceInfo` 供聚合使用

`TraceInfo` 增加：

```python
hallucination_detected: bool = False
risk_level: str = ""
```

`list_traces()` 填充。避免看板为每条 trace 二次 `load`。

### D7. Audit 读取 fail-soft

新增 `JsonlAuditReader.read_all()`：

- 文件不存在 → 空列表
- 单行 JSON 损坏/字段不符 → 跳过并 warning
- 不因一条坏审计导致整个看板 500

### D8. 成本引擎注入 Provider

- `get_provider(..., cost_engine=...)` 新增可选参数
- 自动路由：传给 `RoutingProvider`
- 显式路由：用 route 单价构造 `usage_sink`，调用 `cost_engine.record(route, usage)`
- App 装配时注入 `CostEngine(sink=cost_audit_sink)`
- `cost_audit_sink` 只写 `cost.recorded` 事件，不写 prompt/response

### D9. Ledger 读取走现有 `records()`

- `WriteLedger.records()` 已是只读快照
- 按 `timestamp` 过滤日期
- 只统计 `status=success/failed`，不读取快照与证据链

### D10. 不新增依赖

- 时区用标准库 `zoneinfo`
- JSONL 读取用标准库
- 不引入 pandas/时序数据库

## 5. 聚合服务

`governance/dashboard.py`：

```python
class TraceSource(Protocol):
    def list_traces(self) -> list[TraceInfo]: ...


class AuditSource(Protocol):
    def read_all(self) -> list[AuditEvent]: ...


class LedgerSource(Protocol):
    def records(self) -> list[WriteRecord]: ...


class DashboardService:
    def __init__(
        self,
        traces: TraceSource,
        audit: AuditSource,
        ledger: LedgerSource,
        *,
        timezone: str = "Asia/Shanghai",
    ) -> None: ...

    def overview(self, from_date: date, to_date: date) -> DashboardOverview:
        ...
```

实现要点：

1. 校验范围：`from <= to`，跨度 ≤ 90 天
2. 初始化 `days = [from..to]` 的零桶
3. 遍历 `traces.list_traces()`：
   - `saved_at` ISO 解析 → 转本地时区 → 取 date
   - 在范围内则累加请求/幻觉/降级/风险/延迟
4. 遍历 `audit.read_all()`：
   - `guard.blocked` / `permission.denied` / `dlp.blocked` → 拦截计数
   - `cost.recorded` → 成本/Token/调用数
5. 遍历 `ledger.records()`：
   - `status=success/failed` → 写操作计数
6. 生成每日模型 + 总计（比率按总计重新计算，不相加）

时间解析：

```python
def _local_date(value: datetime, tz: ZoneInfo) -> date:
    if value.tzinfo is None:
        value = value.replace(tzinfo=UTC)
    return value.astimezone(tz).date()
```

坏时间/缺字段跳过该条，不阻断整体。

## 7. API

### 7.1 `GET /v1/dashboard/overview`

Query：

| 参数 | 别名 | 默认 | 说明 |
|------|------|------|------|
| `from_date` | `from` | 今天-6 天 | 起始日期（含） |
| `to_date` | `to` | 今天 | 结束日期（含） |

- 仅 admin
- 日期格式 `YYYY-MM-DD`
- 范围非法 → 422 `invalid_range`
- 时区来自 Settings，不在 query 暴露（避免任意时区导致口径漂移）

响应：`DashboardOverview`。

### 7.2 错误

| HTTP | code | 场景 |
|------|------|------|
| 403 | `forbidden` | 非 admin |
| 422 | `invalid_range` | from > to 或 > 90 天 |
| 422 | `invalid_request` | 日期格式错误（FastAPI 默认校验） |

## 12. 风险与边界

| 风险 | 处理 |
|------|------|
| Trace 文件多导致扫描慢 | 单次 `list_traces`，本地量级；后续可加索引 |
| Audit 文件无限增长 | 本卡不清理；后续轮转/归档 |
| 成本事件缺失（旧数据） | 成本为 0；不伪造 |
| 显式路由未记成本 | `get_provider` 两分支都注入 usage_sink |
| 时区配置非法 | 启动期 `ZoneInfo` 抛错 → fail-fast |
| 比率分母 0 | 返回 0，不抛错 |
| 审计坏行 | 跳过并 warning |
| 权限过宽 | admin-only；manager 403 |
| 成本与预算口径 | 看板按实际 CostRecord；预算按 CostEngine 累计，同源 |

## 13. 学习指引

1. **为什么按天聚合**：运营看趋势，不看单条明细。
2. **时区切日**：UTC 与业务时区的差别会怎样影响“今天”？
3. **比率与总计**：为什么总计的比率要重算，不能把每日比率相加？
4. **数据源分工**：Trace/Audit/Ledger 各回答什么问题？
5. **成本事件**：为什么成本不能直接从 Trace 读？
6. **fail-soft**：坏审计行为什么不能拖垮看板？
7. **admin-only**：为什么 manager 不应看全局成本？
8. **零填充**：为什么缺失日期要返回 0 而不是省略？
